检查依据包括实际资源引用、生成脚本、运行时贴图逐项放大、五关场景截图。旧 README 的数量和“待接入”描述已过期，不能作为当前资源覆盖率的依据。

## 像素检查与验证

生成模型没有严格遵守均匀网格。实际测量原图 alpha > 128 的横纵剖面，发现例如工具图集第一处透明间隔位于 x=633–656，而平均四等分边界是 x=543；平均裁切会切断无人机。使用独立透明间隔测量后，把切点登记在 manifest，导出器按实际切点裁切。

Boss 重排后仍有姿态的矩形包围盒在纵向重叠，不能直接七等分。独立八邻域 alpha 连通检测确认有 **21 个主体区域**，均超过 3000 个源像素，按位置匹配到三阶段/七姿态；导出时提取完整主体、统一缩放和脚底锚点，避免把下一行的头部切进前一帧。零散飘石与极低透明度杂点不作为本体的一部分。

运行时尺寸保持原接口：格子/障碍/触手/炸弹 28×28；敌虫 22×22；保安及多数图标 24×24；Boss 140×64；HUD 牙齿 16×16，飞牙 12×12。原透明 alpha 在保留区域中不做重绘。所有运行时图片经过 alpha 包围盒检查；普通格子贴片有边界留白。触手中段/梢使用无横向留白的拼接规格。

验证流程：worktree 启动 Godot 编辑器导入 → `--headless --import` → 五关实际场景截图与状态展示 → 规则页图例检查。验收脚本检查了单格控件尺寸及 expand_mode、触手加入/释放通路计数、炸弹落地后遮罩数字、全部 21 个 Boss 姿态通过生产脚本加载。最终运行日志输出 `COMPLETION_REVIEW_OK`，没有脚本或资源加载错误。

验收截图采用冻结的关卡重建，不替代用户完整通关游玩；本次没有更改雷位、价格、伤害、CD 或胜负规则。
