## 来源与复现

九套图片由内置 **image_gen** 编辑工具生成，每套引用当前运行角色图，要求只变化一个识别部件。AI 会重新描绘部分像素；这是生成版图片，不保证旧图与新图、各帧机身逐像素完全一致。对照图保留旧图供直接判断。

- [完整提示词与来源清单](../../../visual_v2/source/micro_anim_v1/generation_manifest.json)。
- 生成原始 PNG：`visual_v2/source/micro_anim_v1/{角色}_generated.png`。
- [导出脚本](../../../visual_v2/export_micro_anim_v1.py)：裁切三格，以固定下部轮廓对齐，按原有角色占用尺寸统一最近邻缩小，并输出 PNG 与 GIF。脚本不绘制新的角色像素。

在项目根目录用带 Pillow、NumPy 的 Python 运行 `visual_v2/export_micro_anim_v1.py` 即可从保存的生成图重建交付文件。无需再次调用生图服务。

## 验证与边界

1. PIL／NumPy读取验证了 27 帧的 RGBA 格式、画布尺寸、透明区域和非空主体；逐角色三帧底部基准一致。
2. 九张帧表尺寸正确，裁出的各格与对应独立 PNG 逐像素一致；播放索引与时长有效。
3. 已在实际项目运行 Godot 4.6.1 `--headless --editor --import --quit`，新增贴图导入完成，无脚本解析错误。日志：`tmp/micro_anim_primary_import.log`。
4. 使用九种角色的真实场景检查：机器人渲染单帧 24×24、敌人 22×22；静止、移动、工作时都能切帧，保安播放两帧，其余播放三帧。微循环不修改实体位置或缩放。
5. 游戏未激活、教学提示可见、场景树暂停时，循环与探测／保安工作计时停住；恢复后继续。敌人死亡后停止循环并正常释放。日志：`tmp/micro_anim_verify_verbose.log`。
6. 素材尺寸与场景运行检查不能替代实际棋盘上的游玩观感确认。
