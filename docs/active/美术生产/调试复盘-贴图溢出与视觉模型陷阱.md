# 调试复盘：最右列/最下行贴图"变大"之谜（2026-08-14）

> 一次由用户肉眼发现、agent 三次误判、最终靠"独立峰检测 + 用户标注锚点"破案的渲染 bug。
> 核心沉淀：**视觉模型（图像分析）联动的使用守则**，见文末。

## TL;DR

`Cell.tscn` 的 `Brick`（TextureRect）未设置 `expand_mode`，Godot 4 默认 `EXPAND_KEEP_SIZE`（控件最小尺寸 = 纹理原始尺寸），28×28 的格子被 80×80 的地砖纹理**撑到 80×80**，向右下溢出 52 设计像素。中间格子的溢出被右/下邻格的不透明 `Background` 遮住看不见；**唯独最右列没有右邻、最下行没有下邻，溢出无人遮挡**，地砖直接伸进黑边——看起来就像"最后一列/最后一行的贴图被拉大了"。

修复一行：`Cell.tscn` 的 Brick 节点加 `expand_mode = 1`（EXPAND_IGNORE_SIZE）。

## 症状

- 用户报告："最下面和最右边的贴图都被拉大了……到底是边缘被迫放大，还是整体偏大只是重叠了？"
- 代码层几何计算完全正确：`cell_size=28`，`position=(x*28+14, y*28+14)`，矩形 `offset ±14`，间距=矩形宽 → 每格精确 28×28、零重叠零缝隙。**代码读不出任何问题。**

## 三次失误详析

### 失误1：视觉模型的输出不是测量

- 模型说"完全相等/无明显差异"是**整体印象**，不是逐像素比对；它还会**编造精确数字**（"24像素"）来显得可信——恰好蒙对了一次（真实每格 24px），更具迷惑性。
- 模型第三次（用户标注后）说"大约大 30%"——方向正确、数值不准（真实 ~125%）。**结论：视觉模型适合当"方向性线索"（有没有差异、差在哪），不能当"判定证据"（差多少、是否修复）。**

### 失误2：测量前没验证"测的是对的东西"

- v1 脚本把整张 879×704 全当成"网格"：项目背景 `Color(0.1,0.08,0.05)` ≈ RGB(26,20,13)，三通道和 ≈ 59，"非黑"阈值 30/45 全部失效。
- 正确姿势：**测量前先输出中间结果**（bbox、采样剖面、颜色直方图），人确认"这确实是网格区域"再往下算。

### 失误3：算法预设制造盲区（等距拟合掩盖拉伸）

- v4/v5 用"使 16 条**等距**边界突变总和最大"来拟合网格，再在每条等距点 ±0.4×step 窗口找峰，**最末边界强制锁在搜索端点上**。
- 后果：若最右列真的宽一倍，等距拟合只会把它**平均化摊薄**、端点强制对齐 → 输出"完美等距、0% 差异"。**"拟合很完美"不是数据可信的证据，是算法自我实现的预言。**
- 正确姿势：**独立峰检测**（只找局部极大、不预设间距），配合**外部锚点**（用户标注的 bbox）交叉验证。

## 根因机制（Godot 知识点）

1. **`TextureRect` 默认 `expand_mode = EXPAND_KEEP_SIZE`**：控件 min_size 被设为纹理原始尺寸。纹理是 80×80 的 AtlasTexture → offsets 定义的 28×28 被撑到 80×80，且（anchors 全 0 时）**向右下扩展**：矩形从 `(-14,-14)` 到 `(66,66)`。
2. **Control 绘制顺序 = 树序（后创建的在上）**。Grid 按 y 外层、x 内层 add_child → 每个格子的 80×80 溢出，被右邻/下邻的**不透明 Background（ColorRect）**恰好盖住。
3. **最右列（x=15）无右邻、最下行（y=15）无下邻** → 溢出的 52px 地砖无遮挡伸进黑边。
4. 只有已开格子可见（`Brick.visible` 控制），所以问题是"翻开边缘格子后"出现的。

数值铁证：实测最右列无边界连续区 `620→674 = 54px` ≈ 80 − 26（80px 砖减去被邻格盖住部分，再乘窗口 0.858 缩放）✓；684 后全黑 = 溢出结束 ✓。

### 顺带修复的另外两处

- `project.godot`：`aspect="expand"` → `"keep"`（等比缩放，消除窗口非等比拉伸的整体变形）
- `cell.gd`：`_brick_atlas.filter_clip = true`（防 atlas 相邻砖边缘渗透）

## 🔑 图像/视觉模型联动守则（核心沉淀）

1. **模型输出 = 方向性线索，不是判定证据。** "看起来一样/不一样"可以听，"是否修复/差多少"必须像素级验证。
2. **模型会编造精确数字且很自信**（"24像素""大约30%"）。任何数字必须用独立工具复测。
3. **用户肉眼 vs 模型/算法"没差异"冲突时，默认相信用户。** "没测到差异" ≠ "没有差异"，先怀疑自己的工具有盲区。
4. **像素级视觉问题用像素级工具**（Python numpy/PIL 逐像素：峰检测、亮度剖面、bbox），视觉模型只用来定位/聚焦/描述。
5. **测量前先验证测量对象**：输出中间结果（bbox、剖面、采样值）确认没把背景/整窗当成目标。项目背景色等"预设"要实际核对。
6. **算法预设 = 盲区**：不要用"网格必须等距"这类假设去拟合再宣称"无异常"；改用独立检测 + 外部锚点（用户标注）交叉验证。
7. **用户的朴素描述常是最佳诊断线索**："贴图重叠了还是怎么的"——"重叠"一词正是真相（溢出+遮挡）。
8. **向用户要锚点**：让用户圈出异常位置（红/蓝标注），比任何自动定位都可靠。
