# 宣发计划 v2 —— 零成本验证优先

> 状态：🔄 现行方案（2026-10-05 立，取代同日 v1 的"直接上 Steam"路线）
> 决策依据（用户 2026-10-05 拍板）：**首作不上 Steam，以宣传为主先看市场反馈；反馈好再继续投入（届时再启动 Steam）。**
> 与 v1 的关系：v1 的"攒愿望单→Next Fest→发售"打法整体后移为本计划 P3 阶段（验证通过后执行），核心数据与调研结论已并入本文。

---

## 0. 一句话总策略

**三段式零成本验证：内容数据（L1）→ 免费试玩数据（L2）→ 决策是否上 Steam（L3）。** 在花第一块钱（Steam $100 / 商单）之前，用 6~8 周内容投放拿到市场对这个游戏的真实态度；反馈好，带着已验证的素材和粉丝盘子启动 Steam 路线（仍可赶上 2027-02 Next Fest）；反馈差，换钩子重测或冻结，沉没成本 ≈ ¥0。

为什么这个打法成立：
- 内容平台的推荐算法就是**免费的市场调研**：同一条 30 秒实机视频，"机器人替你扫雷"和"像素美术过程"哪个钩子跑得动，2 周就有答案，比商店页愿望单快且不花钱。
- "担心是粪作"恰好应该用数据回答而不是用焦虑回答：L1 回答"想不想玩"，L2（免费 demo）回答"玩起来行不行"，两级信号都拿到的决策质量远高于拍脑袋。
- Zukowski 的 "Sickos" 理论同样适用：短视频平台会自动把内容推给什么都看一眼的重度尝鲜者，他们的完播/评论行为就是最早的品类试水（来源见 §10）。

## 2. 三级验证框架与阈值

**"市场反馈好"必须先有定义，否则验证结束时还是靠感觉。** 以下阈值为建议值（[B] 经验值，待拍板，§9）：

### L1 内容信号（4 周投放期，B站+抖音为主）

达标线（满足任意两条）：
- 任意 1 条视频自然流播放 ≥ 5 万（B站或抖音）
- 4 周全平台自然涨粉合计 ≥ 500
- "求下载/想玩/蹲"类意向评论合计 ≥ 50 条
- 已开 TapTap/itch 页的话：预约/关注 ≥ 1000

明确不达标：4 周所有视频播放中位数 < 2000 且意向评论 < 10 条。

### L2 试玩信号（免费 demo 放出后 2 周）

达标线（满足任意两条）：
- 下载/领取 ≥ 1000 次
- 回收的存档/问卷中：通关 L3 及以上的玩家占比 ≥ 50%（说明不是点开就关）
- 主动反馈（群/评论区）正面占比 ≥ 70%，且出现自发传播（有人主动晒成绩/推荐）

### L3 决策规则

| L1 | L2 | 决策 |
|---|---|---|
| ✅ | ✅ | 启动 Steam 路线（P3），游戏"值得做"同时"有人想玩" |
| ✅ | ❌ | 游戏有吸引力但品质/留存有问题 → 按反馈返工一轮再验 L2（不上 Steam）|
| ❌ | ✅ | 内容量能弱但产品能打 → 补内容制作能力或小额商单（¥1~2k）再测一轮 L1 |
| ❌ | ❌ | 换钩子重测一轮（共给 2~3 轮机会）；仍无信号 → 冻结项目，回玩法候选库 |

## 3. 总时间轴

关键约束：**Next Fest 2027-02 届的报名窗口大约在 2026-12 中~2027-01 初关闭**（以 Steamworks 后台通知为准）。所以 L3 决策最晚 2026-12 中旬必须做出——这也天然给验证期划了 Deadline，防止无限期测试。

## 4. 分阶段执行

### P0 准备（2026-10 上半月，约 1.5 周）

| 任务 | 说明 | 谁 |
|---|---|---|
| 账号矩阵 | B站（主）+ 抖音 + 小红书，统一用游戏名/「一个人和他的AI同事们」；简介统一挂 demo 领取入口 | 用户注册，AI 出简介/头图/置顶文案 |
| 素材包生产 | 从现有 v0.1 build 批量录实机片段：机器人连锁作业/开墙爆裂/Boss 拔牙/踩雷反转/主菜单剧场——每类 2~3 条 30s 素材，先囤 10 条再开张 | AI（AutoShot 输入注入录制）|
| 发布节奏表 | 4 周 × 每周 2~3 条的排期表，钩子角度预先分配 | AI 出表 |
| 盲测照跑 | 5~10 人封闭盲测与内容验证**并行**，互不阻塞（盲测是质量信号）| 双线 |

### P1 内容测试轮 1（4 周）

四条内容支柱（每条素材只打一个钩子，别混）：
1. **机器人自动化爽点**（主打，差异化）：满配机器人连锁清图的 30s 实录，字幕讲清"你布阵，它们上班"。
2. **扫雷情怀/技巧**（蹭流量）：定式教学、无猜推理，结尾一句"我在做一款机器人替你扫雷的游戏"。
3. **AI 同事人设**（猎奇向）：程序化像素流水线、CogView 质检、一个人+AI 做游戏的过程——首作开发者最容易出圈的角度。
4. **开发日志/试玩反馈**（真诚向）：盲测者怎么骂的、怎么改的——把"怕是粪作"的心态本身做成内容，"独立开发者的第一作"是有共情流量的题材。

执行纪律：
- 每条视频 3 秒内进钩子；B站发完 48h 内切 2 条竖版发抖音；小红书挑美术向素材发图文。
- **每周日复盘**：各条播放/完播/涨粉/意向评论入表（AI 出周报模板）。
- 不投任何付费流量（DOU+ 也先不投）——这一轮要的是**自然流**的市场态度，付费会污染信号。

### P2 免费 demo 放出（L1 达标后）

渠道三层，由快到正规：
1. **网盘直发**（当天可上）：现有外测 zip + B站置顶评论/专栏 + QQ 群。试玩说明.txt 里已设计存档回收方式，直接复用。
2. **TapTap 免费页**（几天审核）：个人开发者认证免费，收预约当 L2 计量器，国内独立游戏氛围好。
3. **itch.io**（可选）：零门槛收 follow，国际向，国内访问一般，优先级低。

配套：放 demo 同步发一条"免费试玩上线"视频（这本身就是内容），建首个玩家 QQ 群（意向评论里的人直接捞进群，是未来 Steam 愿望单的第一批种子）。

L2 数据收集：网盘下载数 + 群内问卷（通关到第几关/最喜欢什么/卡在哪）+ 回传存档。问卷 AI 出，5 题以内。

### P3 验证通过后的 Steam 路线（GO 才执行）

此时才开始花钱（$100）。打法沿用已调研结论，压缩执行：
- 2027-01 Steam 页面上线（素材直接用 P1 验证过跑得动的钩子重剪，mock 文案转正式）+ TapTap 预约页升级。
- 2027-02 Next Fest 全押：demo 用 P2 已被 L2 验证过的版本；商单 8~10 条集中在节中放量（预算 ¥4~6k）；demo→愿望单转化 15~20% 属正常，只看绝对增量；目标愿望单 +3000~5000。
- 2027 Q2 发售：周二~四，首发折扣 10%，发售门槛愿望单 7000+（算法助推经验线）；首周销量 ≈ 愿望单 × 10~20%。
- P14/P15 等大内容开发在 GO 之后才恢复投入（见 §5）。

## 5. 开发侧配套（防"验证期什么都不敢做"）

- **盲测照跑不停**：内容验证回答"想不想玩"，盲测回答"做得行不行"，两个都是 L3 的输入。盲测发现的问题（留存/卡关/差评点）恰好在验证期有空修。
- **小修继续，大开发冻结**：P1/P2 级别的小修和素材润色照做；P14 养成科技树、P15 解锁链等大内容**冻结到 L3=GO 之后**——这是"反馈好了再继续做下去"在开发侧的直接体现。
- 矿工机器人缺口：若 L1/L2 里"想玩矿工线"呼声高，这本身就是市场数据，可提前解锁进 demo 再验一轮。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 内容数据平平但游戏不错（酒香巷子深）| 这本身是重要市场信息：L2 达标 L1 不达标 → 补内容能力/小额商单再测，别急着全盘否定 |
| 4 周测试期越长越焦虑 | 时间轴已硬性限定：12 月中必须 L3 拍板（Next Fest 报名窗口倒逼）|
| 免费 demo 被"免费小游戏"锚定，日后收费有落差 | demo 定位始终是"试玩版"而非"完整版"；TapTap 页面明示"Steam 版将包含 60 关完整内容" |
| 网盘分发无后台数据 | 下载数+问卷+群聊三层补偿；要更强数据再开 TapTap 页 |
| 换钩子两轮仍无信号 | 按决策表冻结项目，弹药（美术流水线/打包线/玩法候选库）全部可复用到下一作——首作验证失败≠白做 |
