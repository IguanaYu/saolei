# 视觉风格标准 v1（暖色像素矿洞风）

> **用途**：S1.1 style guide。所有图像（AI 生成 / 手工调整 / Godot 内配置）必须对照本标准。
> **创建日期**：2026-08-14（地砖已验证通过后定稿）
> **关联**：[AI美术生产指南.md](AI美术生产指南.md)｜[M1-可宣传里程碑-开发主线.md](M1-可宣传里程碑-开发主线.md)

---

## 〇、核心原则（一句话版）

**玩家视线优先级 = 信息 > 机器人 > 格子底 > 环境**。任何元素想"被看见"，就比下一层亮一档、对比强一档；任何元素不该抢戏，就压暗、降饱和。

依据：游戏美术可读性通则（角色/可交互物是最高对比元素，背景降饱和简化）+ 经典扫雷数字配色 30 年验证。参见文末参考链接。

---

## 一、亮度层级表（最重要，可用工具量化验证）

全画面元素按相对亮度（luminance）分层，**相邻层至少差 15-20%**。以已开地砖亮度为基准 100%：

| 层 | 元素 | 目标相对亮度 | 附加手段 |
|---|---|---|---|
| L5 最高 | 数字 1-8、旗、矿脉、跳字/粒子等提示 | **130-160%** | 粗描边或纯白底光晕 |
| L4 | 机器人（含头顶状态气泡） | **115-135%** | 深色 1px 轮廓 + 局部发光件（钻头/雷达） |
| L3 | UI 前景（HUD 数字、按钮文字） | 110-125% | 深色 UI 底板托住，不靠自身亮度硬撑 |
| L2 | 已开地砖（地板） | **基准 100%** | 低对比纹理，砖缝明度差 ≤ 8% |
| L1 | 未开岩石（画面主体但需"安静"） | **70-85%** | 中低饱和暖棕/灰，纹理对比 ≤ 12% |
| L0 | 屏幕外底/棋盘边框外 | 50-70% | 最暗，几乎无细节 |

要点：
- **岩石比地砖暗**（未开=未知=暗，翻开=照亮=亮），天然形成"翻开瞬间变亮"的爽感，替代额外特效。
- 饱和度也分层：L1 岩石饱和度 ≤ 地砖的 70%；机器人饱和度最高（这是"角色从背景里跳出来"的通用做法）。
- 数字必须在地砖上做**深色细描边或投影**（1-2px），任何地砖纹理上都要可读——这是扫雷游戏可玩性的底线。

### 量化验证方法（配合像素工具守则）
用 Python(PIL) 计算素材的相对亮度均值：`L = 0.2126R + 0.7152G + 0.0722B`，逐层对照上表。视觉模型结论只做参考，数字以脚本实测为准。

## 一·五、色彩显著度规则（与亮度分层并行的第二根轴）

亮度分层之外，颜色自身有"抢眼程度"排序，规则如下：

1. **暖前进 / 冷后退**：红橙黄在感知上"往前跳"，蓝绿"往后退"。危险与奖励元素用暖色（警红/矿金），环境和机器人主体用冷或中性色。
2. **饱和度 = 显著度旋钮**：同亮度下高饱和压制低饱和。岩石必须同时满足"暗 + 低饱和"（只暗不灰照样抢戏）；显著度排序：`未开岩石 < 地砖 < 机器人 < 数字/特效`，饱和度也按这个顺序递增。
3. **红绿色觉禁忌**：约 8% 男性红绿色弱。任何"红 vs 绿"的信息区分（如旗 vs 安全、危险 vs 正常）必须叠加亮度差或形状差兜底，禁止只靠红绿色相区分。
4. **保留色原则（最重要）**：**警红 `#c0392b` 与矿金 `#f0c04a` 是保留色**——只允许出现在：雷/坍塌/危险警示（红）、矿脉/金币/开格收益（金）。岩石、地砖、机器人主体、UI 底板一律禁止大面积使用这两个色。这样红/金一闪现玩家不用思考就知道"有事发生"。
5. **相邻层色相错开**：亮度分层的同时色相也拉开（岩石暖棕 → 地砖中性土黄 → 机器人冷色点缀），保证灰度化后仍能分层、彩色时层次更清晰。
6. **色相环间隔**：需要并排区分的元素（4 种机器人、数字 1-8）色相间隔 ≥ 90°，或叠加形状/符号编码。

## 一·六、其余设计轴（形状 / 密度 / 运动 / 时间 / 语义 / 无障碍 / 构图 / 像素技术）

1. **形状/轮廓唯一性**：剪影测试——纯黑剪影下 4 种机器人必须可区分（opener钻头三角/marker旗/detector天线/miner矿斗）；数字用标准字形不加花饰。大面积素材禁止高频碎点纹理（会吃掉上层元素轮廓）。
2. **细节密度预算**：占屏 ~90% 的岩石/地砖只允许"无意义"纹理，禁止出现可识别图形（化石/图案会被玩家误读为线索）；可识别信息只放在小面积元素（机器人/UI/提示）上。
3. **运动显著度分级**：动的比亮的更抢眼。常驻动画（机器人移动、矿脉微光）低幅度低频；事件动画（开格特效/坍塌警告）高幅度。禁止 >3Hz 高频闪烁（光敏安全）。
4. **时间预算**：最高显著层（L5）元素必须短命——跳字 ≤0.6s，警告闪烁 ≤3 次后转常驻图标；长驻元素会被大脑过滤成背景，浪费最高层。
5. **语义符号复用**：旗=标记、骷髅/红=危险、金币/金=收益，优先用通用符号，不自创需学习的图形。
6. **无障碍**：色弱（红绿须叠加亮度/形状差）、低视力（50% 缩放可辨）、光敏（无高频闪）、UI 可缩放。
7. **扫描动线**：扫雷玩家逐行网格扫描，棋盘内禁止跨格大面积视觉元素打断节奏；HUD 核心数字（钱/命）置于视线起点附近（左上）。
8. **像素技术规范**：整数倍缩放；素材边缘对齐像素网格；位移动画帧对齐基准点；全项目纹理 filter 设置统一（像素风用 nearest）。

## 二、调色板（锁 16 色，AI prompt 与手工调整都引用它）

基于已验证地砖（暖棕砖）扩展，向 [Lospec 暖色像素板]（如 Kenney 16 变体）靠拢：

| 角色 | 色值（参考） | 用途 |
|---|---|---|
| 深洞底 | `#1a1410` | L0 背景、UI 底板最深色 |
| 岩石暗 | `#4a3826` | L1 岩石阴影面 |
| 岩石主 | `#6b5138` | L1 岩石主体 |
| 岩石亮 | `#8a6a4a` | L1 岩石受光面（占面积 <20%） |
| 砖缝 | `#5a4632` | L2 地砖缝隙 |
| 地砖主 | `#a8845c` | L2 地砖主体（已验证） |
| 地砖亮 | `#c4a074` | L2 地砖高光 |
| 铜橙 | `#d98a3d` | 机器人点缀/矿脉/充能塔 |
| 矿金 | `#f0c04a` | 矿脉发光、金币、L5 提示 |
| 警红 | `#c0392b` | 雷/危险/坍塌 |
| 旗红 | `#e74c3c` | 旗 |
| 数字蓝 | `#3d7dd8` | 数字1 |
| 数字绿 | `#27a043` | 数字2 |
| 数字红 | `#d63031` | 数字3 |
| 数字紫 | `#7d3cff` | 数字4（5-8 沿用现有 cell.gd 配色微调） |
| 粉白 | `#f5ead6` | 数字描边底、文字 |

规则：
- 新素材**只允许从这 16 色及其中间调取样**，禁止整批素材各带各的色温。
- 机器人识别色（opener黄/marker红/detector蓝绿/miner橙棕）从铜橙/警红/数字蓝/岩石主里派生，保证同源。

## 三、分层素材规范

### 3.1 未开岩石（S1.2 下一个任务）
- 与地砖同规格：**16px 基准格**（Godot 内可缩放），条带 sheet ≥ 4 变体供随机铺设（沿用已验证的地砖"抠块拼接法"）。
- 亮度压到地砖的 70-85%；纹理=粗颗粒裂纹，**禁止**细碎高频噪点（会跟数字抢注意力）。
- 相邻变体之间明度差 ≤ 5%（避免拼出来一块亮一块暗像"提示信息"）。

### 3.2 数字 1-8
- 保持经典扫雷语义色（已实现于 `cell.gd`，用户 30 年肌肉记忆，不改动语义顺序）。
- 每个数字：粉色白底光圈或 1px 深描边，保证在 4 个地砖变体上对比度全部达标（WCAG 式对比 ≥ 4.5:1 目标，实测为准）。
- 数字字号/粗细全棋盘统一，只有颜色变化。

### 3.3 机器人（S1.3）
- 16×16 或 24×24 基准；**颜色 + 形状符号双编码**（opener=钻头三角/marker=小旗/detector=天线/miner=矿斗）——色弱玩家也认得出。
- 待机 2 帧 / 移动 2 帧；AI 只出待机帧，移动帧用 Python 平移+部件摆动合成（实测 AI 多帧一致性不可靠）。
- 全身轮廓 1px `#1a1410` 描边，胸口或工具件带 1-2 像素发光点（铜橙/矿金）。

### 3.4 UI（S1.4）
- 木质/铁框像素主题：UI 底板用 L0-L1 深色（暗底托亮字），边框用岩石主/铜橙双线。
- UI 不用高饱和大面积色块；重要按钮 = 铜橙底 + 粉白字。
- HUD 数字（钱/命/能量）用 L5 级亮度 + 跳动动画，不用加亮底板。

### 3.5 特效/提示（S2）
- 粒子、跳字、矿脉发光统一走"矿金/铜橙"系，最高亮度层，**存在时间短**（≤0.6s），避免常驻元素占 L5。
- 状态气泡（UX.4）：白底深字，尺寸 ≤ 半格。

## 四、AI 生成流程约束（在标准之上生成）

1. 每个 prompt 显式带上：`pixel art, warm cave palette, 16px tile, limited palette` + 上表具体色号。
2. 生成后**必跑像素校验脚本**：亮度层级 ✓ / 边缘无缝 ✓ / 变体明度差 ✓，不达标先 Python 后处理再进 Godot。
3. 一次只生成一类素材（岩石批 / 机器人批 / UI 批），每批与已定稿素材并排对比色温。
4. 素材接入 Godot 时遵守 TextureRect/AtlasTexture 守则（expand_mode=1 等，见 AGENTS.md）。

## 五、验收清单（S1 验收口径）

- [ ] 截 3 张场景图，缩到 50% 后数字仍一眼可辨
- [ ] 灰度化截图后（去色测试），岩石/地砖/机器人/数字仍能按亮度分出 4 层
- [ ] 色弱模拟（灰度+对比保留）下机器人可凭形状区分
- [ ] 剪影测试：4 种机器人纯黑剪影可区分
- [ ] 岩石/地砖上无可识别图形（不产生伪线索）
- [ ] 全部素材并排摆放无"色温打架"，警红/矿金未被背景/UI 大面积使用
- [ ] 无 >3Hz 闪烁；L5 元素存在时间符合时间预算
