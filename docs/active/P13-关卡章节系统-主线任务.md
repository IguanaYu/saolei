## 一、任务背景（Context）

**为什么做这个改造**：扫雷挖矿已实现 P1-P12（局内玩法 + 局外矿石 + 升级树 + 局外解锁），但**完全没有"关卡章节"容器**——玩家面对的是固定的 90 秒冲分模式，没有"卡关-升级-碾压"循环。对标调研（弹壳 290+ 关 / 向僵尸开炮 / 寻道大千）显示，这一品类的留存核心正是关卡制 + 偏量养成。`数值节奏规划-v0.1.md` 已规划 60 关 / 12 章 / 每章末 Boss 关，本任务 P13 落地。

**用户决策（已确认）**：
1. 直接全替代为关卡模式（原 90s 自由冲分模式废除）
2. 5 种目标 + Boss 规则 + 星数判断都接入（最大范围）
3. 每章通关解锁 1 个模块（章 1 opener/marker、章 2 detector、章 3 miner、章 4 tower、章 5 drone）

**关键发现**：充能塔（charge_tower）只在 `main.gd:91` 注释里出现，**实际功能未实现**。所以 ACTIVATE_N_TOWER 目标本期只能数据标记 + 信号接口预留，执行层等充能塔功能落地后接入。

### 数据生成策略：**代码生成，不用 .tres**

理由：60 关高度可模式化（章内 5 关密度乘子 `[1.20, 1.00, 0.85, 1.05, 0.65]` 来自规划文档 spike-valley 模板）；避免手工建 60 个 .tres 的体力活 + diff 噪声；数值迭代改一行即可。

骨架（基于附录 A 数据）：
- `CHAPTER_DENSITY = [0.10, 0.125, 0.13, 0.135, 0.14, 0.145, 0.15, 0.155, 0.16, 0.16, 0.16, 0.16]`
- `CHAPTER_MODULE = ["opener_marker", "detector", "miner", "tower", "drone", "", "", "", "", "", "", ""]`
- `CHAPTER_NAMES = ["新手村", "矿脉谷", "产业链", "充能塔", "硬关峰", "综合境", "进阶域", "深度区", "深渊层", "永恒殿", "终末境", "赛季终"]`

|---|---|

### 关键方法

- `get_level(id) / get_chapter(id) / get_all_chapters()`
- `is_level_unlocked(id)`：章节已解锁 + (首关 OR 上关已通)
- `is_chapter_unlocked(ch_id)`：直接读 SaveSystem

- `mark_cleared(id, stars)`：写通关记录 + 触发下一关解锁；如本关是章末，触发下一章解锁 + 解锁 chapter.unlock_module

### 关键约束
- 模块解锁唯一入口是 `chapter.unlock_module`（章末触发），`RewardData.unlock_id` 留空，避免双重解锁路径

## 八、关键代码片段

### LevelSystem 解锁链核心
```gdscript
func mark_cleared(id: String, stars: int) -> void:
    var prev := SaveSystem.get_level_stars(id)
    SaveSystem.set_level_cleared(id, max(prev, stars))
    var lvl := get_level(id)
    var chapter := get_chapter(lvl.chapter_id)
    if chapter.level_ids[-1] == id:  # 章末
        var ch_idx := chapter.id.substr(2).to_int()
        var next_ch := "ch%02d" % (ch_idx + 1)
        if next_ch != "ch13":
            SaveSystem.unlock_chapter(next_ch)
        if chapter.unlock_module == "opener_marker":
            pass  # 默认就有，无需操作
        elif chapter.unlock_module != "":
            SaveSystem.unlocks[chapter.unlock_module] = true
            SaveSystem.unlock_changed.emit(chapter.unlock_module)
            SaveSystem.save_game()
```

### ResultsPanel 首通/重刷分支
```gdscript
func _on_game_over(result: String) -> void:
    show()
    if result == "lose":
        result_title_label.text = "失败"
        stats_label.text = "再接再厉"
        return
    var level_id := GameState.current_level_id
    var stars := _calculate_stars(level_id, result)
    var is_first := not SaveSystem.is_first_clear_claimed(level_id)
    var lines := ["星数: %d/3" % stars]
    if is_first:
        var r := LevelSystem.claim_first_clear(level_id)
        lines.append("首通奖励: +%d 矿" % r.ore)
    else:
        var ore := LevelSystem.get_level(level_id).repeat_reward.ore
        SaveSystem.add_ore(ore)
        lines.append("重刷奖励: +%d 矿" % ore)
    LevelSystem.mark_cleared(level_id, stars)
    result_title_label.text = "首通胜利" if is_first else "重刷胜利"
    stats_label.text = "\n".join(lines)
```

## 九、风险与权衡

1. **充能塔 ACTIVATE_N_TOWER 目标本期失效** [B]：充能塔功能未实现，目标数据标记 + GameState 加 `tower_activated` 信号接口预留；Boss 关 ACTIVATE_N_TOWER 改为 SURVIVE_TIME 兜底（数据生成时若章 4+ 涉及塔则用 SURVIVE_TIME 替代）。**后续 P14 接入充能塔后激活此目标类型。**

2. **reset_state 签名变化漏改调用点** [B]：默认参数 `level_id=""` 兼容 results_panel.gd:29 旧调用；实施前 grep `reset_state(` 确认全仓调用点（预期仅 2 处：main.gd、results_panel.gd）。

3. **SaveSystem v2→v3 升级丢字段** [A]：现 L41-43 已是"逐字段合并"模式，对 4 个新字段重复同样模板；删存档 + v2 旧档测试必做。

4. **章节级模块解锁与解锁信号重复** [B]：强制约束 RewardData.unlock_id 全部留空（仅给 ore），模块解锁唯一入口是 chapter.unlock_module。

5. **LevelDatabase 与 LevelSystem 初始化顺序** [B]：project.godot autoload 顺序必须 `GameState → SaveSystem → LevelSystem`；LevelDatabase 是 RefCounted，由 LevelSystem._ready 内 `LevelDatabase.new()` 触发构造。

6. **60 关数据全是占位，玩家很快发现内容雷同** [C]：本期目标是 schema + UI + 流程跑通；Boss 关通过 forbidden_actions（禁标雷）+ 不同目标类型制造差异感；数值深度后续 P14-P15 调整。
