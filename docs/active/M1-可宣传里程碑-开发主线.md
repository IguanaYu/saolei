# 扫雷挖矿 · M1 可宣传里程碑开发主线

> **阶段定位**：M1 = 第一个"可宣传 / 可市场验证"的里程碑。目标不是"功能做完"，而是"**能录一支 30 秒让人想玩的宣传视频，能上 Steam Next Fest / TapTap 收愿望单**"
> **创建日期**：2026-08-13
> **前置决策**（2026-08-13 已定）：平台 = PC（Steam/TapTap）；范围 = 精炼 demo（1-2 章）；美术 = AI 生成 + 整合；视觉风格 = 待拍板（建议起步见 §四）
> **关联文档**：[T2-主线开发文档.md](T2-主线开发文档.md)（本文档调整了 T2 的重心）｜[P0改造方案-微信小游戏体感.md](P0改造方案-微信小游戏体感.md)｜[游戏设计文档.md](游戏设计文档.md)

## 一、M1 是什么

### 1.1 定义

M1 = **Marketable Demo**。一个**玩起来有手感、看起来像成品、第一次玩的人能玩通、能录视频做宣传**的版本。

它**不是**"所有功能做完的正式版"，也**不是**"留存/商业化优化版"。它是让市场第一次看见、第一次判断"这游戏值不值得期待"的版本。

### 1.2 验收锚点（反推法）

> **"能录一支 30 秒、发出去让人想愿望单的宣传视频。"**

视频里要展现出什么，M1 就得有什么：

| 视频要展现 | M1 必须做 |
|---|---|
| 扫雷开图的爽快 | Juice（跳字/粒子/缩放）+ 音效 + 视觉风格 |
| 机器人产业链在"活"着 | 机器人移动动画 + 矿脉发光 + 卸货数字弹跳 |
| 关卡推进的成长感 | 前 1-2 章真实内容 + 基础局外升级（变强感） |
| 第一眼辨识度 | 定视觉风格 + 一套美术资产 |
| 新人能玩下去 | 新手引导 + 完整流程闭环 |

### 1.3 核心判断

项目当前**"骨架完整、皮肉全无"**：玩法机制层（扫雷核心 + 4 机器人产业链 + 局外矿石 + 60 关章节框架）已足够支撑可宣传版本。最大缺口不是"更多机制"，而是**表现层 + 手感 + 闭环收尾**。因此 M1 的重心是**做皮肉**，不是加骨架。

## 二、范围界定（In / Out of Scope）

### 2.1 In Scope（M1 必做）

- 视觉风格定义 + 一套基础美术资产（格子/机器人/UI）
- 核心 Juice + 音效/音乐
- 前 1-2 章（约 8-10 关）真实可玩内容 + 新手引导
- 补功能债：**充能塔实现**（已承诺未做，绑 ACTIVATE_N_TOWER 目标）
- 基础局外升级偏量养成（P14 压缩版，每项 2-3 级，核心 3 项）
- 1 个卖点小机制（锁格 或 扣分格，作 demo 记忆点）
- 2 个新关卡目标（OPEN_N_NUMBERS / ACCUMULATE_MONEY）拉关卡差异
- 发布准备：商店页素材 + 打包 + 设置菜单

### 2.2 Out of Scope（明确推到 M1 之后）

| 推后项 | 原归属 | 推后理由 |
|---|---|---|
| P15 嵌套解锁链 | T2 Sprint 4 | 留存优化，非宣传必需；等 demo 数据再做 |
| P16 近失补偿与失败激励 | T2 Sprint 3 | 留存优化，非宣传必需 |
| 第 5 种机器人 | 玩法发散 | 现有 4 种够用，新机器人推迟 |
| 操作暴击/词条系统 | 玩法发散 | 留给 T3 装备系统 |
| 装备/多角色/社交排行/商业化 | T3+ | 远期 |

> ⚠️ **这是与原 T2 主线的最大调整**：把重心从"留存优化（P15/P16）"转向"表现+内容打磨"。理由：P15/P16 是"发布后按留存数据迭代"的事，而 M1 的目标是"先让市场看见"。详见 §三。

## 四、视觉风格方向

> 完整调研见 2026-08-13 视觉风格调研报告（本会话产出）。以下为结论。

### 4.1 四个候选选项

| 选项 | 风格 | AI生成 | 扫雷可读 | 产业链活感 | 紧张感 | 关键参考 |
|---|---|---|---|---|---|---|
| 🥇 **暖色像素矿洞风** | 暖棕底+4色矿脉+chunky方块机器人 | 极易 | ★★★★★ | ★★★★ | ★★★★ | Dome Keeper / Brotato / Mindustry |
| 🥈 冷感科技扁平风 | 深蓝全息+荧光，产业链如电路板流光 | 易 | ★★★★★ | ★★★★★ | ★★★ | Hexcells / Factorio |
| 🥉 暗调发光爽快风 | 黑底霓虹，截图最炸 | 难 | ★★★（发光盖数字=硬伤） | ★★★★★ | ★★★★★ | 20MTD / Vampire Survivors |
| 4 卡通拼贴风 | 圆润拟人机器人 | 较难 | ★★★★ | ★★★★★ | ★★（与紧张冲分冲突） | Oddsparks / Islanders |

### 4.2 建议起步风格：暖色像素矿洞风

**决定性理由**：
1. **AI 可行性最高**（单人 imagegen 出图的生命线，像素是 AI 最稳区间）
2. **扫雷数字可读性最稳**（本项目死亡线是"看不清数字"，暖色压平格+粗描边数字彻底规避）
3. **四项适配度无短板**，不像选项3偏科、选项4与情绪打架
4. **情绪曲线可调**：前期静谧暖色 → 后期粒子+发光矿脉沸腾，匹配玩法节奏

**混血优化**：主体暖色像素，但矿脉与 miner 拖尾借用一点选项3的发光特效（像 Dome Keeper 水晶），兼顾可读性与炸眼感。

> **待决策点 V1**：视觉风格最终拍板（默认采用暖色像素矿洞风，可改）。见 §九。

## 五、开发主线 Sprint 划分

> 工期估算：单人开发，总计约 **18-24 天**（含 gate）。可按精力压缩或并行。

### Sprint 1：视觉定义 + 美术基建（关键路径起点，5-7 天）

> 阻塞一切表现层工作。视觉风格不定，S1 无法启动。

| 任务 | 内容 | 产出 |
|---|---|---|
| S1.1 | 视觉风格定稿：拍板选项，出 moodboard + 色板 + style guide（锁定调色板/字号/描边规范，控制 AI 一致性） | style guide 文档 |
| S1.2 | 格子美术：未开岩石 / 已开地砖 / 数字1-8 / 旗 / 矿脉 / 坍塌 / 基地 / 充能塔 | 格子精灵集 |
| S1.3 | 机器人美术：4 种（颜色+功能符号双编码：opener钻头/marker旗/detector雷达/miner矿车）+ 待机/移动 2 帧小动画 | 机器人精灵集 |
| S1.4 | UI 框架美化：HUD / 商店 / 升级面板 / 主菜单 / 章节/关卡选择 / 结算，统一像素木质/铁框主题 | UI 主题 |
| S1.5 | 字体选定（像素字体，数字粗描边） | ttf 资源 |

**验收**：能截 3 张不同场景图，发给不认识的人能看出"这是个挖矿机器人游戏"。

### Sprint 2：Juice + 音效（手感核心，4-5 天）

> 这是宣传视频的灵魂。把"干"变"爽"。

| 任务 | 内容 |
|---|---|
| S2.1 | 开格反馈：+1 跳字、尘土粒子、格子缩放弹动 |
| S2.2 | 标雷反馈：旗子插下动画、+5 跳字 |
| S2.3 | 踩雷反馈：屏震、红色全屏闪光、坍塌裂纹动画、低沉音效 |
| S2.4 | 产业链反馈：矿脉脉动光、miner 移动拖尾、卸货数字弹跳+金币飞出、基地闪光 |
| S2.5 | 升级/购买反馈：按钮按压、金币消耗飞出、升级满级光效 |
| S2.6 | HUD 反馈：分数跳动、倒计时后期红光+心跳音效（损失厌恶）、命数可视化 |
| S2.7 | 核心音效：开格/标雷/踩雷/购买/升级/卸货/胜利/失败 + 1 首循环 BGM |

**验收**：录一段 30s 视频，无声也觉得爽、有声更爽。

### Sprint 3：内容打磨 + 闭环（6-8 天）

> 让 demo 有真实可玩内容、新人能上手、补功能债。

| 任务 | 内容 |
|---|---|
| S3.1 | 新手引导：第 1-2 关教学（放基地 → 开图 → 买第一个 opener → 标雷），带高亮提示框，可跳过 |
| S3.2 | 新目标类型：`OPEN_N_NUMBERS`（开够 N 个数字格）/ `ACCUMULATE_MONEY`（累计赚 N 钱）落地到 `objective_data.gd` + `main.gd:_update_objective_progress` |
| S3.3 | 前 2 章（约 8-10 关）真实数据细化：密度梯度、目标类型分布、forbidden_actions 制造差异 |
| S3.4 | **充能塔功能实现**（补功能债）：`tower_activated` 信号落地 + 范围充能 buff + `ACTIVATE_N_TOWER` 目标可用 |
| S3.5 | 基础 P14 偏量养成：核心 3 项（global_speed / expand_zone / start_robot），每项 2-3 级偏量值（如 speed `[2.0,1.4,0.8]`），扩展 `effects: Array[Dictionary]` |
| S3.6 | 1 个卖点小机制：**锁格子** 或 **扣分格**（二选一，作 demo 记忆点），地图生成时撒点 |

**验收**：找一个没玩过的人能自己玩通前 2 章，不卡死、能看懂。

### Sprint 4：发布准备（3-4 天）

> 让 demo 能打包发出去做市场验证。

| 任务 | 内容 |
|---|---|
| S4.1 | 商店页素材：icon / 5 张截图 / 宣传图 / 30s 宣传视频 / 一句话 slogan / 详细描述 |
| S4.2 | 打包构建：Godot export Windows，干净环境测试能跑 |
| S4.3 | 基础设置菜单：音量 / 画质 / 键位说明 + ESC 暂停 |
| S4.4 | 上架准备：Steam 页面搭建 / TapTap 页面，开启愿望单收集 |
| S4.5 | bug 清扫 + playtest（5-10 人，收第一轮反馈） |

**验收**：能发给朋友试玩 / 提交 Steam Next Fest。

## 六、缺口清单（M1 工作项来源）

## 七、风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| **视觉风格未拍板** | S1 关键路径阻塞，全网延期 | §九 决策点 V1 立刻定 |
| AI 美术一致性 | 风格漂移、素材打架 | S1.1 出 style guide 锁调色板/描边规范，每批素材对照 |
| 单人开发工作量 | Sprint 滑期 | 严格 gate，每个 Sprint 结束评估再进下一个 |
| 90s 短局平衡 | 雪球失控或过难 | S4.5 playtest 校准 |
| 宣传视频抓不住卖点 | 市场验证失败 | S4.1 视频脚本先写，突出"扫雷+自动产业链"反差 |
