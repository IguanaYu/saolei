# 高塔地图(40行×25列·双视口平滑切换)— 实施计划 v1

**日期:** 2026-10-04
**需求(用户原话):** "地图是40行25列。一开始只显示底下的25行25列,点击上,可以显示上边的25行25列。中间有一个平滑的过渡。"
**性质:** 调研报告 B+A 方向的首个落地切片(任意尺寸地图 + 视口滚动),先做"离散视点+补间"而非自由相机——工程量小一个数量级,且正好验证"棋盘形状无关地基"的结论。
**上游:** [可行性调研-异形地图与多格障碍-v0.md](玩法设计/可行性调研-异形地图与多格障碍-v0.md) §2(A 方向卡点清单)/§3

## 1. 设计方案

### 1.1 结构:BoardRoot 容器 + Grid 缩放 + Grid 位移

```
Main
├─ CaveEnv(屏幕空间,V2 背景不变;岩框改为挂进 Grid)
└─ BoardRoot (Node2D, scale=适配系数 s)   ← 新增
   ├─ Grid        (scale=1, position 携带视口滚动偏移)
   ├─ RobotManager / EnemyManager / BossManager (原样搬入)
```

- **s = min(1.0, play_w/(cols·cell), play_h/(visible_rows·cell))**,visible_rows = min(rows, 25)
  → 40×25 盘:s = 508/700 ≈ 0.726,可视窗=25 行=508px,宽度 508px 恰好落在两侧日志栏之间;
  → 16×16/每日挑战等现有关:s=1,**渲染零变化**。
- **滚动 = tween grid.position.y**(BoardRoot 本地坐标,unscaled 单位):可视窗顶对齐 play_area 顶。
  视点状态只有两个:bottom(rows-visible)与 top(0),步进=可视窗高,40 行盘正好 15↔0。
- **岩框进 Grid**:cave_env 的 frame 改挂 grid 子节点(z_index=-1,网格本地坐标),随滚动/缩放自动跟。
- **兼容性核心**:`coord_to_world` 语义从"全局坐标"改为"BoardRoot 父容器本地坐标"——今天所有 manager
  恒等变换下二者相等,**robot.gd/enemy.gd/boss_manager.gd 一行不改**;`world_to_coord` 改走
  `global_transform.affine_inverse()`(输入路径正确处理缩放+滚动)。

### 1.2 交互

- 上/下箭头按钮(UILayer,悬于 play area 顶/底中央,半透明),仅当该方向还有地图时显示;
- 鼠标滚轮上下=步进滚动(与按钮同一步长,复用同一补间);
- 首基地落位后自动滚到基地所在视口(玩家不会"基地在屏外");
- 补间 0.45s ease-in-out;补间期间每帧 reproject 机器人/虫(管理器现成接口)。

### 1.3 关卡

- 新增 ch01_s06「高塔」:grid_size=Vector2i(40,25),150 雷(15%),CLEAR_ALL_SAFE 打折线 300/850,
  时限 300s,玩家自放基地(fixed_base=(-1,-1)),无虫无 Boss(纯验证地图机制);
  数值为原型占位,验证滚动体验后再调。

## 3. 风险

- 恒等性破坏(现有关渲染变化)→ S2 单测逐点比对旧公式,S1/S3 截图 diff 兜底;
- 选关页 6 格布局挤爆 → 看 set_chapter 布局,必要时收紧间距(只动 ch01);
- 1000 格 Solver/BFS 性能 → 预算是 16×16 的 ~4 倍,<1ms×4 可接受,实测帧率确认;
- 滚动中机器人/虫视觉滞后 → 补间每帧 reproject(实体数少,开销可忽略)。

## 4. 明确不做(v1)

- 自由拖拽相机/边缘滚动/缩放;高塔关数值调平;虫害/Boss 适配;每日挑战高塔化。
