## 0. 执行者必读的项目规矩

- **运行验证**（来自 CLAUDE.md，引述原样）：
  `"E:\其他\chorme_download\Godot_v4.6.1-stable_win64.exe\Godot_v4.6.1-stable_win64_console.exe" --path "e:\godot\扫雷"`
  每改一页必须实机运行截图核对，不能只看代码。
- **git 提交不添加 Co-Authored-By**。
- 优先用 Edit 工具直接编辑，不用 Python 补丁脚本。
- 新增节点要显式命名，避免 `get_children()` 遍历误匹配。
- **任何新玩法机制先过 [玩法解构方法论-v1.md](玩法设计/玩法解构方法论-v1.md) §5 验证四问**；铁律：已揭示数字与雷位永不变动；自动化不吞噬玩家的模糊推理层（solver 不许加超出两条局部确定规则的推理）。
- 像素级视觉问题必须用 numpy/PIL 实测，视觉模型结论不算验收证据；TextureRect + AtlasTexture 必须设 `expand_mode=1`。
- use worktree 时须先开一次 Godot 编辑器模式再启动游戏。

## 2. 阶段 A：范围与数据定稿

### A1 LevelData 增加展示字段

`scripts/data/level_data.gd` 加三个字段（布局计划 §2.2 建议）：

```gdscript
# ---- 试玩版展示字段（选关页/关前卡直接读，不重复维护文案）----
var short_name: String = ""      # "自动扫雷"

```

同时在 `_apply_playtest_levelN` 里赋值，选关页/关前卡/HUD 全部从这读。

### A2 新目标类型 OPEN_N_SAFE

布局计划 §0：过关由扫雷进度决定。现有 `CLEAR_ALL_SAFE`（清空全部）在 90 秒局里太重，需要"开 X/Y 安全格"阈值目标。

- `scripts/data/objective_data.gd`：`Type` 枚举加 `OPEN_N_SAFE`，复用 `target_value` 存 X。
- `scripts/main.gd`：`_on_cell_opened` 里对 `OPEN_N_SAFE` 累计已开安全格，`_update_objective_progress()` 刷新 HUD，达到 `target_value` 调 `_end_game("win")`。参考现有 `FLAG_N_MINES` 的写法（`_on_cell_flagged` L700-705）。
- Y（安全格总数）由 `grid` 提供，进度条显示 `X/Y`。

### A3 解除 detector/miner 的局外解锁门槛（试玩关）

`scripts/ui/shop.gd` `lock_reason()` L113-123：对 `lvl.is_playtest` 的关卡跳过 `SaveSystem.unlocks` 检查，只保留 `is_module_allowed`（关卡口径）：

```gdscript
if robot_type == "detector":
    var lvl0: LevelData = GameState.get_current_level()
    if lvl0 == null or not lvl0.is_playtest:
        if not bool(SaveSystem.unlocks.get("detector", false)):
            return "检测型未解锁（通 2-5）"
    if not GameState.is_module_allowed("detector"):
        return "本关禁用检测型"
```

miner 同理。（L1 的 `shop_hidden` 已不含 detector/miner、`allowed_modules` 为空 = 全允许，只差这道门槛。）

**阶段 C 验收**：玩家不看说明能区分资金/目标/积分；机器人空闲时侧栏能看出原因；买不了设备时卡上写明真实原因；购买成功后资金变化与机器人出生位置肉眼可见。

## 5. 阶段 D：关卡与教学

### D1 L1 重做（最大单块工作）

1. **盘面**：`scripts/data/fixed_boards.gd` 重做 L1 常量——预开区保证 opener/marker 立即有确定推理链（solver 只有两条局部规则，盘面必须喂给它确定步）；场内预置若干已标雷位（给 detector）、至少一条与基地连通的矿脉（给 miner）。用 Python 脚本离线验证盘面确定可解性再写进常量。
2. **时限**：90 秒；教学气泡打开时暂停计时——`main.gd _process()` L413 的门控改为：
   ```gdscript
   if not GameState.game_active or GameState.tutorial_pause:
       return
   ```
   `tutorial_guide` 每步显示/隐藏时置位（或 director 调用）。
3. **教学剧本**：`scripts/level1_director.gd` 重写为两段——先"买开墙/标雷→看机器人开格"（含一次卸货前的资金回览），后"检测确认雷→矿脉→矿工运回"。首次购买四类不强迫顺序（Factorio 复盘结论，布局计划 §5）；新机制只各出一条短提示。
4. **数值**：`start_gold` 按"免费阶段收入 + 初始金 ≈ 首购两台基础机（100）+ 尽快能买 detector(80)/miner(60)"设计，模拟 2–3 条投资路线验证 90 秒内可达标且能见一次卸货。

### D2–D5 其余四关

- D2 L2：维持现结构，数值与文案对齐；确认 `meta_progression=false`。
- D3 L3：目标换 OPEN_N_SAFE（若 §5-2 拍板）；再投资考题=作业收入追加设备；结算埋点 `crossing_elapsed` 改为 OPEN_N_SAFE 过线时刻。

- D5 L5：新增 `scripts/level5_director.gd`（只一句开场白）+ `main.gd` L116-127 创建、L265-272 挂接 `ch01_s05` 分支。

### D6 教学时序修复

### D7 可玩性自测

模拟（脚本驱动或人工快进）至少 3 条投资路线 × 5 关：全可达标、无卡死盘面、目标阈值不能被纯手点轻易越过、也不需要买齐四类才赢。记录进盲测基线表。

**阶段 D 验收**：五关均可达标；首关 90 秒内能看到首次购买、机器人自动开格/标雷、至少一次矿工卸货；教学气泡期间倒计时不动。

## 10. 风险

- **L1 时间预算最紧**：90 秒内要完成首购 + 看到自动扫雷 + 一次卸货；教学暂停计时是硬前提，数值必须模拟验证。
- **solver 弱**：盘面没有确定步机器人就闲置；解法是设计确定可解的预开区（铁律：不给机器人加推理能力来"修"这个问题）。
- 布局计划的像素坐标是首版目标，实机截图后必然微调，不作为验收硬门槛；验收门槛是可读性与信息层级。
- 旧存档兼容：cleared_levels 可能含 ch02+；选关页只列 ch01 五关即可规避，但要实测旧存档进"继续试玩"的推导不指向第六关。
