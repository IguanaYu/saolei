# 扫雷挖矿：外部试玩版 v0.1 页面布局与实施计划

> 2026-09-28。承接[页面与关卡范围分析](外部试玩版-v0.1-页面与关卡范围分析.md)及用户确认的方案。此文是实施计划，不代表页面和关卡已经修改。设计基准为项目当前 1024×768 逻辑视口、Windows 鼠标操作、V2 深色矿洞/铜框主题。所有尺寸是首轮布局目标，运行截图后微调。
> **✅ 2026-10-01 执行状态**：本文信息架构已落地（主菜单/单章选关/关前卡/规则页/结算账单/试玩完成页/暂停重做，详见范围分析头部复核注）。文中"90 秒"等时限表述已被"按关配置（120–210s）"取代（盲测批次 903757f）；"第五关无新系统"的范围已被 L5 Boss 关设计推翻（见第五关-设计文档 §13）。

## 0. 目标与固定规则

- 封闭试玩只显示**一组 5 关**，按前关达标顺序解锁；主菜单直接进入这组关卡。
- 第一关让玩家亲手购买开墙、标雷，并在本关看见检测、采矿及至少一次矿工卸货。四类设备都能买，但不强迫按固定顺序买齐。
- 过关由扫雷进度决定；检测/采矿提供局内资金与附加分。局内购买扣资金，不扣积分。计时关提前达标按剩余秒数加分。
- 90 秒是挖矿局目标时长；首关教程或说明覆盖层出现时暂停计时。到点或命尽正常结算本局收益，未达标不解锁下一关。
- 暂不显示 12 章、星数、每日挑战、签到、分享占位、未生效音频和震动选项。虫害、保安、探测留在后续版本或单独的测试分支，不塞进这五关。
- 第 1–5 关的目标数值、雷数、初始资金和设备价格是关卡设计阶段的校准参数；本计划规定其呈现位置和可理解性，不预先捏造平衡值。

## 1. 信息层级和导航

```text
启动 → 主菜单 → 试玩关卡选择 → 关前卡片 → 局内 → 结算
                  ↑                  │       │      ├─ 达标：下一关
                  └──────────────────┴───────└─ 未达标：重玩/选关

局内暂停 → 继续 / 操作与规则 / 重开 / 返回选关
主菜单 → 设置 / 操作与规则 / 反馈 / 退出
第 5 关达标 → 试玩完成页 → 反馈 / 选关 / 主菜单
```

首次进入：`开始试玩` 直接选中第 1 关并打开关前卡片，最多两次点击进棋盘。已有进度：主按钮改为 `继续试玩 · 第 N 关`；`选择关卡` 是次按钮。按钮的文字由存档推导，不能出现“继续”却跳回第一关。每个覆盖面板有明确返回位置；ESC 只返回上一层，不跨层跳转。

## 2. 具体页面布局（1024×768）

### 2.1 启动与主菜单

沿用现有整屏矿洞背景，背景压暗以保证文字可读。启动页只保留 LOGO、真实加载状态、`封闭试玩 v0.1`；若无实际加载，短暂展示后进入菜单，不做假进度条。

主菜单内容集中在中央约 `x=292–732` 的 440 宽区域：

```text
上方 80–250     徽记 / 扫雷挖矿 / 一句话玩法：“投资机器人，推进雷区”
中央 300–375    [继续试玩 · 第 N 关]  —— 最亮、最大
      390–440    [选择关卡]
下方 485–535    [操作与规则] [设置]
底部 690–744    封闭试玩 v0.1  ·  反馈  ·  退出游戏
```

“总矿石”在菜单右上角小标签显示，永久升级入口不放在主按钮上方；玩家首次完成第 2 关后，在选关页间场提示“矿石可换开局加成”并提供 `变强` 按钮。反馈入口必须配置实际可用的 URL、二维码或随包说明路径；地址确定前用设置项配置，不在包里放“开发中”。

### 2.2 关卡选择与关前卡片

关卡页使用左右两栏，保留当前矿洞背景。页面标题 `试玩矿区 · 进度 X/5`，右上总矿石和 `变强`；左上返回主菜单。

```text
x=40–354，y=110–635       五个纵向关卡行，每行约 90 高
  01 自动扫雷  ✓/当前/锁      每行：编号、名称、状态、一行新机制
  02 增机还是提速
  03 再投资
  04 基地布局
  05 综合矿区

x=390–984，y=110–635      当前所选关详情
  大标题 + 本关一句考题
  目标：例如“90 秒内完成安全格进度 X/Y”
  本关新增设备/规则（最多两条）
  已完成时显示最佳得分与最佳用时；未玩显示“尚无记录”
  底部 [开始本关/重玩本关]；锁关显示“通关第 N 关解锁”
```

第一次打开可玩关时，点击开始先弹轻量关前卡片：`本关目标 / 本关可用设备 / 时间和结束规则 / 开始挖矿`。重玩时可勾选或自动记住“跳过说明”，但暂停中的规则页仍可查。卡片只显示当前关配置出的真实数字，不重复维护硬编码文案。建议沿用 `LevelData` 加 `short_name`、`intro_line`、`mechanic_tags` 等展示字段。

### 2.3 局内：棋盘始终居中

以 16×16 棋盘约 448×448 为最大内容基准，中央 `x≈288–736，y≈136–584`；10×10/14×14 盘保持同中心，允许格子稍放大但不改变左右信息区的边界。最高视觉对比留给数字、旗、矿脉和机器人，矿洞背景继续降暗。

```text
y=8–72：顶部 HUD
  左 x=16–238       本局资金 ¥ N（可花），下方短说明“购买设备”
  中 x=270–750      第 N 关 + 扫雷目标进度 X/Y + 细进度条
  右 x=784–1008     积分 N | 时间 1:30 | 生命 | 暂停

y=128–584：中心棋盘
  左 x=16–260       队伍概况：开墙/标雷/检测/矿工各 N 台；工作/空闲状态
  中 x≈288–736      棋盘
  右 x=764–1008     本局得分：开格、正确标雷、采矿；事件短提示

y=606–752：底部操作台
  第一行：四张设备购买卡（名称、用途、现价、现有台数）
  第二行：建基地 / 局内升级 / 操作说明 / 放置取消提示
```

第一关可以让设备购买卡全部可见，并用“当前是否有工作目标”辅助说明；后续关卡按配置显示或禁用，禁用原因直接在卡上写明。买不起显示差多少资金；限购显示“已购满”；缺少可工作的矿脉显示“需先检测”之类的真实条件。购买成功后，资金变化和机器人出生位置必须可见。

队伍概况的目的不是显示一堆数值，而是让玩家判断投资是否有效：例如 `开墙 2 台 · 1 台空闲`，空闲时能指向“暂无可推理目标”。右侧分数区让玩家看出“采矿是加分，扫雷是目标”。小盘首关左右留白较多，可以用较大文字；大盘仍以棋盘可读为先。若 1024×768 下侧栏遮挡或文字不足，可收为左右各一张可展开卡片，但顶部目标、资金与底部购买必须常驻。

操作规则常驻于暂停帮助：左键开格、右键插旗/撤旗、机器人自动工作、购买后需放置、暂停和取消放置。新机制只在第一次遇到时用一条短提示，不用连续弹窗占用 90 秒。

### 2.4 暂停、规则与确认

暂停面板居中约 `520×500`，背景暗化，顶部显示关名与当前目标进度；主按钮 `继续挖矿`，次级 `操作与规则`、`重新开始`、`返回选关`。重开和返回均弹确认框，说明本局是否结算及会保留多少收益。游戏树暂停时应允许设置、规则和确认框交互；关闭后倒计时恢复。

规则页用 3 个固定小节：`怎么扫雷`、`四类机器人做什么`、`资金/目标/积分如何区别`。从主菜单可打开完整规则，从局内暂停打开时默认跳到当前关新增规则。

### 2.5 结算与试玩完成

结算面板约 `620×560`，棋盘仍可透过暗背景看到，但不可操作。信息从上到下：

1. 状态：`目标达成` 或 `本次挖矿结束 · 目标未达成`；紧跟目标进度 `X/Y`，不以“失败”或“时间到失败”命名。
2. 分数账单：开格分、正确标雷分、采矿附加分、剩余时间加分、最终积分。没有取得的分项也显示 `0`，让计分规则稳定可读。
3. 局外收益：本局获得矿石与是否解锁下一关；买机器人/升级的支出只体现在剩余资金，不从积分里扣。
4. 按钮：达标时 `[下一关]` 为主按钮，`[重玩] [返回选关]` 为次按钮；未达标时 `[重玩本关]` 为主按钮，`[返回选关]` 为次按钮。

第 5 关达标后进入试玩完成页，显示 `5/5 关完成`、本次试玩总用时、最高分、反馈入口。不要展示尚未制作的第 2 章或“完整版即将解锁”假入口。

## 3. 五关的页面节奏与内容安排

| 关 | 关前只讲一句 | 局内首次亮相 | 结算让玩家看见 |
|---|---|---|---|
| 1 自动扫雷 | “亲手买机器人，让它们接手扫雷。” | 开墙/标雷先获得工作目标；检测确认雷；矿工运回第一批矿 | 机器人完成多少开格/标雷，采矿得分；第一笔购买与第一次卸货的时间 |
| 2 增机还是提速 | “同一笔钱，添机器人或升速度？” | 局内升级和时间奖励 | 不同投资对应的完成时间及时间加分 |
| 3 再投资 | “利用作业收入扩大队伍。” | 收入再投入；若保留永久成长，在本关前引入一次 | 投资前后扫雷进度速度是否改变 |
| 4 基地布局 | “基地位置会改变往返时间。” | 第二基地与矿工运输距离 | 不同布局对应的运矿次数/附加分，仍以扫雷达标为主 |
| 5 综合矿区 | “用自己的投资路线冲高分。” | 没有新系统；组合前四关选择 | 完整分数账单和试玩完成反馈 |

首关计时从玩家结束第一条交互教学后开始，教学气泡打开时暂停计时；保留 90 秒局的完整操作时间。首关盘面预开并设置一段可直接推理的开场，保证开墙/标雷能立即工作；随后自然出现可检测旗位及可采矿脉。目标阈值不能让玩家单靠手动点击轻易越过，也不能要求买齐四类设备才算赢。关卡数据设计时用多条投资路线模拟，再用真人盲玩检验。

## 4. 实施顺序与验收门槛

| 阶段 | 改动范围 | 完成条件 |
|---|---|---|
| A 范围与数据定稿 | `LevelDatabase/LevelData`、关卡规则、5 关短名称与目标；统一 90 秒语义和扫雷达标口径 | 五关均有独立数据；第一关检测/矿工可用；第五关不再是旧生存 Boss；文档与代码数值一致 |
| B 导航骨架 | 主菜单、选关、关前、暂停、结算、完成页；移除章节跳转及长期入口 | 新存档两次点击进首关；旧存档也只能看到 5 关；ESC/重开/返回/下一关路径完整 |
| C 局内信息 | HUD、四设备卡、队伍状态、分数来源、规则页 | 玩家不看说明也能区分资金、目标、积分；知道机器人为何空闲、为何不能买 |
| D 关卡与教学 | 重做 L1–L5 内容；四类机器人、采矿、升级、再投资、基地布局 | 五关均可达标；首关出现首次购买、自动扫雷与矿工卸货；无卡死盘面 |
| E 结算与收益 | 到点/命尽、时间加分、采矿分、矿石入账、解锁；清除调试入口 | 到点正常结算但不解锁；提前达标加分；重复插旗无法刷钱/分；重启游戏进度一致 |
| F 视觉与外测包 | 1024×768、窗口/全屏检查、版本与反馈入口、导出 | 核心文字在 100% 和 75% 缩放可读；无占位按钮；干净 Windows 环境完整跑通五关 |

开发顺序先做 A，再 B/C/D 并行局部推进，之后 E/F 集成。每完成一页在 Godot 实机截图核对：按钮能点、文案与数值一致、无覆盖棋盘；再检查 16:9 常见窗口尺寸。使用新存档和已有存档各走一遍，避免旧章节进度污染试玩入口。盲测指标沿用现有计划：首关购买/机器人首次开格和标雷/首次卸货时间、关卡达标率、机器人与玩家扫雷比例、错误日志和玩家实际投资选择。

## 5. 设计依据与限制

- 本项目既有 V2 矿洞主题和[视觉风格标准](视觉风格标准-v1.md)已规定“信息 > 机器人 > 地砖 > 环境”，所以先改信息层级，不重做美术。
- [Factorio 开发者对新手流程的复盘](https://www.factorio.com/blog/post/fff-241)强调早期展示核心自动化、让玩家实验而非照购物清单执行；本方案据此要求首关早见机器人工作，但不强迫固定购买顺序。这是对本项目的设计推断。
- [Steamworks Demo 文档](https://partner.steamgames.com/doc/store/application/demos)建议试玩内容聚焦真实核心体验；本方案据此只展示包内有完整结果的入口。封闭 Windows 外测包并非 Steam Demo，引用仅作内容取舍参考。
- 反馈地址、玩家可领取的局外矿石比例、五关目标阈值、各机器人价格与机器人求解能力仍需在阶段 A/D 用可玩数据校准；界面必须读关卡配置生成文案，避免计划数值与运行数值再次分叉。
