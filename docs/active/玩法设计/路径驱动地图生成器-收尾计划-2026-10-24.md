# 路径驱动地图生成器 · 收尾计划（2026-10-24）

前置：步骤 1-2 已完成（规则模拟器+对拍 10 种子、路线分析+布雷修补循环、S 形示例
30/30 种子、Godot 重放验收），测试体系见[实施进展](路径驱动地图生成器-实施进展-2026-10-23.md)。

## 调研结论（本轮补充）

- 编辑器实现：Godot 官方推荐自定义 `Control` + `_draw()` + `_gui_input()` 做网格
  绘制工具（[官方文档](https://docs.godotengine.org/en/stable/tutorials/2d/custom_drawing_in_2d.html)），
  独立工具场景比 EditorPlugin 轻量，符合"开发工具不进游戏 UI"的定位。
- 封印机制：设计文档 §7.3 语义与 lock-and-key 文献一致——
  [Boris the Brave 的 lock-and-key 形式化](https://www.boristhebrave.com/2021/02/27/lock-and-key-dungeons/)
  （已在设计文档引用）、[Unexplored 的循环地牢生成](https://www.gamedeveloper.com/design/unexplored-s-secret-cyclic-dungeon-generation-)
  、"teaser 门"模式（先让玩家看到锁住的区域，建立解封预期）支持"清楚的关联标记
  与解除反馈"的要求。本项目"领土连通才触发"是供给线变体，与现有 territory 机制同源。

## 执行顺序与范围

### A. 生成盘接入关卡（先做，让产物可玩）
1. `FixedBoards` 新增 `R1` 常量（seed 2 示例盘，墙经 `reinforced_walls` 字段）。
2. `level_database.gd`：ch01 扩到 8 关，`_apply_route_gen_s1` 配 CLEAR_ALL_SAFE
   目标/经济/模块白名单（同 L4 风格，pests=false——生成的盘无虫害/锁）。
3. 确认 `main.gd` 固定盘装载链对 walls 的传递（CH2 已用，预期无需改）。
4. Godot 测试 `tests/route_gen_level_test.gd`：LevelSystem 取关 → Grid 装载 →
   参考动作重放 → 终态与 Python 报告一致；选关页可见性断言。
5. 验收：headless 全过；实机可进（启动一次让用户能玩）。

### B. 化石主动规划（§12 第 3 步）
1. `generate.py`：`fossils_max` 上限（总面积 ≤ 8 格，§7.1 不许沿 S 两侧铺满）；
   修补杠杆扩为 墙满 → 锁满 → **化石 2×2** → 换雷（化石挡洪水/机器人工位、
   减少线索，与预开/锚点/基地/雷/其他化石不重叠——对齐 apply_fixed_board 拒铺口径）。
2. 对比实测：走廊冲突种子在"化石启用/禁用"两组下的合格率变化（§3"效果必须验证"）。
3. 验收：`selftest_pipeline` 加化石杠杆用例；对比数据记入文档。

### C. 区域封印机制（§12 第 4 步，工作量最大）
游戏侧（ch01 规则面 = 统一权限检查覆盖当前全部揭格通道）：
1. `cell.gd`：`is_sealed` / `seal_id` / `apply_seal` / `release_seal` + 视觉占位
   （程序绘制封印标记，素材后换）。
2. `grid.gd`：`seal_groups`（id→{cells, trigger, released}）；`apply_fixed_board`
   支持 `"seals"`；开/标/和弦/洪水拦截 sealed（独立于锁的状态）；开格批次后
   `_check_seal_triggers()`——trigger 已开且在 `player_territory()` → 整组解封 +
   `seal_released` 信号（main 接 toast）。
3. 探针：sealed 格"未扫描"——不确认、零命中也不给安全信息（main._trigger_probe +
   对拍两侧同口径）。
4. 机器人：作业目标排除 sealed（同锁格口径）；封闭格未开不可走天然成立。
5. 激光/精灵/爆炸的封印拦截留 §12 第 5 步（文档注明，不静默宣称支持）。
生成器侧：
6. `rules.py`：Board/SimState 支持 seals；四类动作拦截；probe 未扫描口径；
   触发解封（opened ∩ territory）。
7. `generate.py`：封印杠杆——skip/大跨度 corridor 反例在墙锁化石修不动时落
   封印组（cells=危险走廊格，trigger=路线上保护段之前的锚点格）；上限 2 组
   （§7.4）；约束：trigger 不在任何封印区、依赖无环、cells 不含锚点/trigger；
   解封后 reference 全程复验（触发可达性自动验证）。
8. 对拍扩展：`tests/route_gen_parity.gd` 场景支持 seals；动作含"开 sealed 被拦/
   探针跨封印/触发解封/解封后开格"，Python-Godot 逐项比对。
9. 测试：`selftest_rules` 加封印用例；Godot `tests/route_gen_seal_test.gd`
   （手工小盘：拦截/触发/解封/探针未扫描/洪水不穿/机器人不作业）。

### D. 编辑器画线工具 v1（最后做，独立可裁）
1. `scenes/tools/RouteEditor.tscn` + `scripts/tools/route_editor.gd`：
   Control `_draw()` 网格 + `_gui_input()` 左键加点/右键撤销；叠加显示吸附路径、
   阶段锚点、走廊提名、段间距过近预警（<5 格标红，§4.3 高冲突提示）。
2. 保存/加载笔画 JSON（`tools/route_gen/strokes/`）；一键调用
   `python -m tools.route_gen.cli`（OS.execute 异步），完成后载入
   `out/board_fixed.json` 画答案层叠加（雷/预开/墙/化石/封印，可开关）。
3. 定位：开发工具场景（编辑器 F6 运行），不进选关 UI；Python 为生成逻辑唯一源。

### 明确不做（记录于文档）
- 机器人物理行走/工时、激光束封印拦截、精灵封印拦截（§12 第 5 步）；
- 阈值校准（等试玩数据）。

每步完成即 git 提交（不带 Co-Authored-By）；C 步游戏侧改动跑一次全量 headless
回归（规则自检/管线自检/parity/seal 测试/既有 tmp 关键测试抽查）。
