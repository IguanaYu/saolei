# 第二章钻石效果系统 · 开发计划

日期：2026-10-22。更新：2026-10-23。状态：**四类效果首版代码与第二章试用配置已实现；整体尚未最终验收，随机预览两项检查、旧入口回归、真人体验与经济调参待继续完成**。

实施记录：[钻石效果系统-实现与验收-2026-10-23.md](钻石效果系统-实现与验收-2026-10-23.md)。下文保留原始开发计划；其中“建议”“未来开发”“本次未执行”描述的是 10 月 22 日编写计划时的状态。此次按 D1–D10 首版建议作工程默认实现，不将它们记为用户另行拍板；金币、射程和精灵参数可继续调整。

需求来源：本轮讨论中用户最后明确的四类钻石效果及“保留激光、保留扫雷底子”的约束。此前助手提出的采钻通关、回声追加打击、改变发射点等方案，不属于本计划需求。

## 1. 已确定的开发范围

在现有第二章上增加“不同钻石携带不同效果”的能力。首批覆盖四类：

| 效果 | 用户已确定的内容 | 本计划中的暂用 ID |
|---|---|---|
| 范围激活 | 激活周围 9 格 | `area_3x3` |
| 随机双射线 | 随机向两个方向射出 | `split_two` |
| 金币 | 直接给予金币 | `gold` |
| 探索精灵 | 召唤一个探索精灵 | `explorer` |

以后可以继续增加效果类型。首版先让每颗钻石对应一种效果；一颗钻石同时携带多种效果，不在本轮范围内。

以下基础保留：

- 扫雷的相邻数字、开格、标记、零格连开，以及现有求解规则。
- 激光的发射操作、现有射线几何、贯穿方式、动作次数和冷却规则。
- 现有机器人、商店、升级和积分通关体系。
- 正确标记、开格和碎钻等基础奖励；新效果的收益单独记账。

本轮先针对第二章的点击式激光接入。第三章持续光束、第四章工会及第一章关卡只做兼容回归；它们接入钻石效果应另列工作，不能顺手启用。

## 2. 开发前需要明确的规则

**下表“首版建议”是为了使计划可执行而提出的默认口径，不是用户已经确认的规则。** 开发负责人先收敛这一页，再开始效果实现；当前编写计划不要求用户立刻回答。

| 编号 | 待定事项 | 首版建议 | 影响范围 |
|---|---|---|---|
| D1 | 如何激活钻石 | 沿用讨论主线：正确标记后，被激光命中才激活；标记本身不释放效果 | 主触发流程、教学 |
| D2 | 一次性还是反复触发 | 每颗钻石每局释放一次；重开恢复；撤旗、重插和重复命中不能刷新 | 经济、状态、连锁收敛 |
| D3 | 是否允许钻石互相激活 | 新钻石范围/射线命中另一颗已正确标记钻石时，可以连锁；未标钻石不会自动变成已保护的触发器 | 连锁玩法、误打风险 |
| D4 | “周围 9 格”的范围和作用 | 解释为含中心的 3×3；中心负责释放，不重复破坏自身。外围按下文交互表处理 | 范围效果实现 |
| D5 | 新效果命中未标钻石会怎样 | 建议沿用现有空间伤害的碎钻语义，不能免费替玩家识别并保护。须专门试玩评估误开远处区域的体验 | 扫雷基础、连锁风险 |
| D6 | 双射线方向和长度 | 从八方向随机选两个互异方向；射程配置化，原型可先借用现有特殊矿石的 3 格作为比较起点 | 随机性、范围、表现 |
| D7 | 金币数量 | `gold_amount` 配置化；具体金额在经济试玩阶段确定，不与分数自动双重入账 | 商店节奏、奖励 |
| D8 | 精灵的探索能力 | 建议为临时自动探索单位：依据公开数字寻找确定安全的格子，不读取隐藏雷位挑目标；有效作业次数、间隔和寿命待定 | 精灵行为、扫雷难度 |
| D9 | 钻石类型何时可见 | 建议正确标记后显示效果图标和说明；未调查格保持统一覆盖，预览不得提前暴露钻石或类型 | 美术、信息权限 |
| D10 | 旧设施效果能否触发新钻石 | 首版建议主束、折光副束及新钻石产生的空间效果可触发；旧矿石/过载爆炸先保持原有不扩展新级联的约定 | 旧关兼容、连锁复杂度 |

若 D1–D5 调整，应先同步状态流和交互表，再改效果代码。尤其不能在开发过程中默认加入“全部自动保护”“激活后变安全格”或“改成采集通关”。

## 3. 代码现状与复用边界

本节基于当前工作区的只读检查。路径用于后续开发定位，不表示这些文件已经修改。

| 现有位置 | 已有能力 | 计划中的衔接 |
|---|---|---|
| `scripts/data/level_data.gd`、`level_database.gd` | 关卡参数与固定盘配置 | 增加按关卡启用的钻石效果配置；空配置保持原玩法 |
| `scripts/cell.gd`、`grid.gd` | 雷位、标记、碎钻、墙层数、零格展开 | 承载或查询钻石效果状态；继续由 Grid 执行基础开格和碎钻 |
| `scripts/laser/laser_manager.gd` | 主/副束几何、命中集、单轮去重、充能与结算 | 接入效果队列，统一计算新增范围与连锁，再完成整枪结算 |
| `scripts/laser/laser_geometry.gd` | 格心连线与八方向工具 | 复用双射线几何，不另写一套斜向算法 |
| `scripts/facilities/chain_node.gd` | 3×3 格集、一次消耗与连锁演出 | 复用范围计算和演出经验；不能直接把钻石变成安全格设施 |
| `scripts/facilities/special_ore.gd` | 随机方向抽样、射线结果与特效共用 | 复用算法思路；不能继承它的 2×2 足迹、三方向和无限次触发规则 |
| `scripts/solver.gd`、`robot.gd`、`robot_manager.gd` | 基于公开数字的确定动作、单位调度和清理 | 复用精灵的决策依据与生命周期经验，避免直接复制完整机器人购买链 |
| `scripts/main.gd`、`autoload/game_state.gd` | 奖励通道、统计、胜负和开局重置 | 为新奖励加来源，补齐状态重置，保证整枪结束后再判胜 |
| `scripts/effects_layer.gd` | 激光、爆炸、充能和浮字 | 接入四种可区分的效果反馈 |

当前最直接的冲突：`LaserManager.fire()` 遇到旗格会直接跳过。新入口必须先处理“可激活的已标钻石”，随后仍跳过旗格的普通破坏。**免于破坏和允许激活需要分开表达。** 普通错误旗格不能因此获得钻石能力。

当前按整枪对墙体、机器人和敌人去重；本计划默认继续沿用，不能借接入新效果悄悄变成同格多次伤害。

## 4. 建议的数据与模块划分

### 4.1 配置与运行状态分开

每颗钻石的静态定义包含：坐标、稳定效果 ID、效果参数。固定盘优先显式配置，便于复现和单独验证四种效果。

每局运行状态包含：未激活、已排入结算、已消耗，以及本次触发来源。重开时重建，不写回共享关卡资源。

- 雷位与效果类型分开保存。改变效果不改变雷位、雷数或数字。
- 已消耗钻石仍然按原雷位参与邻格计数；不能因为效果用完而减少数字或被求解器当成安全格。
- 正确旗的基础奖励仍由已有首次奖励账本管理；“效果已用完”使用独立状态。
- 未配置效果的钻石维持原行为；非法坐标、未知效果 ID、无效参数在载入时报告，不能静默随机替换。

### 4.2 最小可扩展结构

建议新增一个钻石效果管理模块，职责为读取配置、判断触发、维护状态、调度处理器和输出结果。使用效果 ID 注册四个处理器，避免把所有类型分支继续塞进主场景和 Cell。

一次射击共享一个结算上下文，包含：

- 当前局标识和射击标识。
- 待处理效果队列、已入队钻石集合。
- 普通空间命中集、机器人充能集、敌人命中集。
- 金币奖励、精灵召唤请求和表现事件。
- 本次实际随机结果。

上下文可以先使用小型数据对象或结构化字典；不要求重写现有激光架构，也不建设通用技能编辑器。

后续增加第五种效果，通常只需增加一个效果定义、处理器、表现及对应验收，不应复制开格、标记、冷却或整套射击流程。

## 5. 触发、连锁与结算规则

以下按 D1–D10 的首版建议描述。

1. 发射入口沿现有规则检查并记账；整枪只消耗原有的一次玩家动作，不擅自改变消耗时点，附带效果不额外消耗动作。
2. 获得原有主束、副束及既有设施几何。按来源策略识别可激活的已标钻石，加入队列。
3. **钻石入队时即记录为已排入结算**，不能等播放动画时再消耗。
4. 依次处理队列。范围/双射线扩展命中集，并把它们命中的其他合格钻石加入队列；金币和召唤只增加对应请求。
5. 队列收敛后，统一执行空间命中、充能、奖励与召唤，提交消耗状态和统计。
6. 全部即时结果完成后走现有胜负检查，再播放或继续播放表现。不得因为中途分数达标漏掉后续金币与召唤。

精灵以后产生的作业属于后续游戏过程，按每次作业走原有开格与判胜通道；不要求等精灵寿命结束才结算胜利。

### 5.1 去重与顺序

- 同一颗钻石每局至多释放一次效果；本枪多路命中或回环不能重复入队。
- 同一格整枪至多执行一次常规削层/破坏，范围重叠不自动增加伤害次数。
- 同一机器人整枪最多获得一次同档充能；同一敌人沿用原有单轮受击上限。
- 旧矿石、过载、折光和节点也共享本枪的对象触发记录；不能因为两条新副射线分别调用几何计算，就让同一对象超出原有单轮触发次数。
- 多颗金币钻石分别给各自奖励，多颗精灵钻石分别提交召唤；不能按坐标重叠丢掉独立效果。
- 使用稳定的队列顺序和独立随机源，使固定局面、固定种子可复现。
- 队列上限由本局可触发钻石数量自然约束；不使用递归扩散。若出现异常超限要报告原因，不能悄悄少发奖励。
- 本枪触发资格以射击开始时的标记状态为依据；开格连开不等于自动识别并激活新的钻石。

### 5.2 新空间效果的对象交互建议

| 对象 | 3×3 范围 | 随机双射线 |
|---|---|---|
| 普通未开格 | 走原有开格；满足零格条件时原有连开继续生效 | 同左 |
| 多层墙、覆盖墙 | 整枪最多削一层，复用原通道 | 同左 |
| 已标且未消耗的效果钻石 | 入效果队列，自身免于普通破坏 | 同左 |
| 已消耗钻石、普通旗格、化石 | 保留原保护/阻挡语义，不重复发奖 | 同左 |
| 未标钻石 | 按 D5 最终选择执行；不得自动标对再触发 | 同左 |
| 开墙/标雷机器人 | 建议沿用既有矿石/过载范围的充能口径，整枪去重 | 沿用激光充能口径，整枪去重 |
| 筑墙工 | 沿用既有命中伤害和单轮去重 | 同左 |
| 折光、旧矿石、过载、旧节点、引光柱 | 范围只执行对应原有范围受击语义；首版不新增一套旧设施级联 | 副射线复用现有射线规则；旧设施自身的级联约定不扩张 |

实施时需把最后一行展开成逐对象测试，尤其不能把 2-5 的旧连爆规则全局改成另一套。

## 6. 四种效果的工作内容

### E1：周围 9 格激活

- 四类钻石使用图标或形状配合颜色区分；正确标记且未激活、已消耗两种状态应在小尺寸下可辨，不能仅靠颜色变化。
- 按最终确认的范围定义生成格集；若采用 3×3，边缘、角落和异形盘洞区只保留实际存在的格。
- 中心钻石先消耗，周围已标钻石可接力；重叠范围走统一去重。
- 提供短范围闪光、格子受击和钻石接力反馈。只播放震动不执行逻辑，或重复播放导致重复结算，均不算完成。
- 已公开钻石的确定范围可预览；未知钻石不能凭预览暴露位置。

验收：中心 3×3、边角裁切、重叠削层一次、两颗互相覆盖仅触发各一次、含金币/精灵钻石的混合连锁均符合规则。

### E2：随机两个方向射出

- 方向数固定为两个；方向集合、射程和选取约束由配置控制。
- 只在实际触发时抽样一次；将方向和格集保存到本次结果中，逻辑与动画使用同一份结果。
- 悬停不能推进实际随机序列，也不能画一条看似确定、实际却会换方向的射线。
- 首版预览可展示“随机两方向”标识与最大可能范围，明确这是可能范围，不声称两条实际方向已经确定。
- 保留斜射几何、盘外裁切和原有射线对象交互。

验收：固定种子可复现、两方向互异、八向候选可被覆盖、悬停次数不改变结果、动画与真实命中一致，密集连锁不会随机重抽多次。

### E3：直接获得金币

- 触发时通过现有金币通道增加配置金额，使用独立来源（建议 `diamond_effect_gold`）。
- 原正确标记奖励继续只给一次；效果金币不能再次冒充标记奖励或开格奖励。
- 金币效果本身不额外开格、不发射射线、不自动转换为本关目标分。
- 显示明确的金币浮字和余额变化，避免和“+分”混淆。

验收：重复射击、撤旗重插、多路连锁、重叠命中都只发一次；多颗金币钻石合计准确；重开不继承上一局消耗状态或余额。

### E4：召唤探索精灵

建议首版采用独立的临时单位管理，不进入商店价格阶梯、机器人限购或机器人总数计算。

- 从钻石上空出生，不强行打开出生格，不要求把旗格改为可行走地面。
- 可复用求解器输出，选择公开信息能够确定安全、仍可作业且未被其他单位锁定的格子。
- 飞行移动和简化表现可作为首版建议；能否穿越地形不等于可以无视锁格、化石或信息规则开目标。
- 先实现一种作业行为：自动开确定安全的格子。是否标雷、是否探测未知、是否给其他单位增益，留到后续扩展。
- 可作业次数、行动间隔、寿命、无确定目标时等待还是离场，以及单局并存上限，属于 D8 的待定参数。
- 多精灵共享目标预留，目标被别人打开后重新选取；不重复作业或重复发奖。
- 精灵行动产生的金币/分数使用独立来源，但奖励数值沿用所执行的基础开格行为。
- 暂停时停行动；胜负、退出、重开和换关时停止并清理，旧回调不能在新关召唤或开格。

验收：正常召唤和作业、无确定目标、重复召唤、多精灵抢目标、暂停恢复、关卡结束和换关均覆盖。改变隐藏雷位但保持公开输入一致时，精灵的目标选择应一致；不能调用“直接筛掉真实雷位”的工具方法伪装推理。

若最终决定精灵具有显式探测未知的能力，应另写探测次数、信息揭示与风险规则；不能由开发者暗中加入全知选点。

## 7. 开发顺序与交付物

每一步只在专用验证盘或效果开关开启的关卡运行。表内验收是未来开发任务，本次没有执行。

| 工作包 | 开发内容 | 可交付结果与完成标准 | 依赖 |
|---|---|---|---|
| WP0 规则收敛 | 确认 D1–D10、对象交互表和精灵首版行为 | 一页确定规则及参数表；已确定与待试玩数值区分清楚 | 无 |
| WP1 最小纵向流程 | 配置、状态、管理器入口、旗格激活、金币效果、重开清理、最小图标/浮字 | 正确标记一颗金币钻石后，激光命中只发一次金币；关闭功能的关卡行为相同 | WP0 |
| WP2 范围与连锁 | 3×3 效果、队列、混合金币链、空间去重、基础接力演出 | 一枪触发范围钻石并激活金币钻石；重叠、回环、边界均正确 | WP1 |
| WP3 随机双射线 | 随机抽样、几何复用、随机预览表达、射线混合链 | 固定种子重放一致；逻辑/画面同源；可连到范围或金币钻石 | WP2 |
| WP4 探索精灵 | 独立生命周期、公开信息决策、目标预留、开格奖励 | 钻石召唤精灵并完成规定行动；无目标、暂停和换关可收尾 | WP2；混合验收接 WP3 |
| WP5 完整反馈与兼容 | 四类型识别、说明、已消耗状态、连锁演出、来源统计、真实输入验证 | 玩家能区分四类及状态，随机性表述真实，旧关回归完成 | WP3、WP4 |
| WP6 机制试玩 | 四类单项盘、混合盘和有意误打案例 | 验证简单推理后的一枪多效；记录误开、连锁收益、精灵有效行动和可读性问题 | WP5 |
| WP7 关卡与数值接入 | 选择正式关卡、配置类型比例/金额/射程/精灵参数、教学、地图安排 | 基于已验证规则制作关卡；每关新增重点明确，目标仍为原积分体系 | WP6 |

先完成金币纵向流程，是为了最早验证真实输入、旗格激活、消耗与账本衔接。四种能力都在首批开发范围内，不能以“金币已经可用”代替其余效果交付。

地图制作放在机制验证之后；单项验证盘只是工程与玩法试验工具，不提前锁定第二章五关的重新分配。

## 10. 试玩观察与数值工作

在四种规则可用之后，再确定具体金额、射程、精灵次数和关卡比例。先记录：

- 玩家正确标记了多少颗、激活了多少颗、误碎了多少颗钻石。
- 一枪触发的效果类型、连锁长度、实际影响格与新增数字数量。
- 金币效果收入、由此改变的购买时机；不把新收入自动加为额外目标分。
- 精灵召唤数、有效作业数、待机时间和重复抢目标情况。
- 随机射线造成的可理解收益与非预期远处开格；单独询问玩家是否觉得失去控制。
- 玩家能否说清楚“这颗钻石是什么效果”“为何这枪发生连锁”，以及连锁画面是否遮住数字。

通过后的地图工作再考虑小组连锁、不同效果组合和简单推理入口。不能先用宝石铺满地图，再反过来要求机制适应。
