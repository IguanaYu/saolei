## 3. 工作包分解

### WP1 折光机器人实体（驻点单位）

1. 新建 `scripts/robots/refractor_robot.gd` extends [Robot](../../../scripts/robot.gd)：构造参 `config: String`（`"wide"`/`"scatter"`）；**覆写 `accumulate_and_maybe_tick()`/`do_tick()` 为空**——不寻路不作业不参与 Solver/工作分配（驻点语义）；`is_stationary = true` 标志供寻路/索敌排除。
2. 两型 = 两个 robot_type：`refractor_wide` / `refractor_scatter`（**共享脚本**、构造传 config；独立 type 才能各占一个 `shop_limits` 键与独立计价——2-2 调研节"最干净是两个独立 robot_type"结论落案）。
3. 注册八处清单（照抄 agent 盘点）：robot_manager 场景 const + match（[robot_manager.gd:7-10,28-32](../../../scripts/robot_manager.gd#L7-L10)）、game_state 计数字段/reset/价格/purchase/gift（49-53/358-362/446-498；base=100 限购 1 不翻倍）、Shop.tscn 两按钮 + shop.gd（`@onready`/`BUTTON_ICONS`/`_on_buy_*`/`_refresh_one`/`shop_extra` 开闸）、显示名映射（[main.gd:1037](../../../scripts/main.gd#L1037)/1146、[event_log_connector.gd:11](../../../scripts/ui/event_log_connector.gd#L11)）、`is_module_allowed` 白名单（game_state 374-380）、皮肤 SHEETS 预留（micro_sprite_loop 4-14，先兜底色块：宽束=横向双箭头蓝、散射=三叉橙，`FactionMarker.attach` 上阵营描边）。
4. **占格与通行**：折光所在格加入占用集（opener/marker 寻路 `spaced_targets` 排除；builder 施工排除——2-2 WP3 排除表加"折光格"）；本体不阻挡激光（激光在它格上**终止并转化**，不是被挡）。

### WP2 光束接管（多束结算架构启用）

1. LaserGeometry 补两个函数（2-1 单测框架扩 case）：
   - `corridor_cells(origin: Vector2i, dir8: Vector2i, length := 6) -> Array[Vector2i]`：沿 dir8 主轴 1..length 的超覆盖线 + **垂直向 ±1 偏移两条平行线**，合并去重（宽 3 格走廊；边界裁切）；
   - `scatter_cells(origin, dir8, length := 6) -> Array[Vector2i]`：dir8、dir8 左旋一格、右旋一格（八向量化后的 ±45°）三条超覆盖线合并去重。
   - 斜向入射的 45° 定义=**八向旋转**（octant ± 1），统一栅格规则的核心口径（设计 §7"斜向命中采用统一栅格规则"）。
2. laser_manager.fire 改造（仍在"快照→去重→结算"框架内，只是快照阶段变多段）：
   - 主束超覆盖推进，**遇第一台折光格即止**（该格收入命中集）→ 按入射 octant（`octant_dir(上一格, 折光格)`）出副束：wide=`corridor_cells`、scatter=`scatter_cells`；
   - 副束格全部并入本轮命中集（同一 per-cell/per-enemy/per-robot/per-node 去重集合——"交叉副束不会把三层墙瞬间打穿"由集合天然保证）；
   - **副束不再激活第二台折光**（visited set 标记；副束经过其他折光格只当作普通已开格）；
   - 副束能力=充能/对敌/削墙/触发节点（2-4 起），与主束同规则；主束在折光格之前穿过的机器人先充能再增幅（设计 §6"不互相抢效果"——推进顺序天然满足）。
3. 预览同步：LaserPreview 悬停计算主束+（若截停）副束整集高亮——预览与结算调**同一个** `compute_shot_geometry(base, target) -> ShotGeometry`（新抽公共函数，fire 与 preview 共用，杜绝两套规则漂移）。

### WP3 购买与放置流

1. 商店购买折光（任一配置）→ **不直接落位**，进放置模式 `_enter_placing_mode("refractor_wide"/"refractor_scatter")`（[main.gd:928-944](../../../scripts/main.gd#L928-L944)）：确认前不扣钱（购买延后到落位成功，非法落点不吞单位——设计 §6）。
2. 悬停预览：落点合法色 + **该落点出射范围轮廓**（假设从基地典型入射方向；简化口径=显示以落点为源、四向走廊/散射全展示或仅当前悬停方向——决策 Q2）+ 主基地→落点入射连线。
3. `place_block_reason`/`can_place_at`（960-993）加规则组：仅已开安全格；排除旗格/已转化资源/连爆节点(2-4)/引光柱(2-5)/基地/**其他单位所在格**（含机器人当前格——动态检查）。
4. 落位：`robot_manager.spawn_robot(coord, type, ...)` 指定格（不走 BFS）；扣钱走 `purchase_robot`；出生演出沿用 `play_spawn_drop`（1137d65 出生链自动生效）。

## 4. 实施顺序与里程碑

```
M1 几何完备 ──── WP1 实体+注册 → WP2 接管+compute_shot_geometry 抽取（单测对拍扩 case）
```

- M2 验收：宽/散各买一台完成一次增幅；非法落点零损失。
- M3 验收：预设驻点开局即用；六断言过；三条投入路线（单用宽束/加散射/升级普通机）模拟可玩。

## 6. 决策记录与待定问题

- **Q1 散射 ±45° 的八向量化**（已定）：任意斜率的精确 45° 旋转在栅格上无定义，八向旋转（octant ± 1）是唯一确定性口径；预览=结算同源保证无争议。实测看玩家理解成本。
- **Q2 放置预览方向口径**：悬停预览显示四向全轮廓（信息全但噪）vs 仅当前基地入射方向（贴实战但依赖站位）——**推荐后者**（基地固定，入射方向事实确定）。
- **Q3 折光不进快捷键**（已定）：放置型交互与直购型不同质；1-4 键位语义保持"直购落基地旁"。
- **Q4 预设赠送驻点若被玩家预先放单位占位**：进关顺序上赠机先于玩家操作（`_start_level_with` 367-382），不可能冲突；断言进实测。
- **Q5 折光被束命中的"格"语义**：折光格收入命中集（该格已开，无副作用），副束从折光格**下一格**起算（不重复算折光格自身）——写入单测防歧义。
