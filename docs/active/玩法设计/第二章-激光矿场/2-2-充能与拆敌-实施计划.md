## 3. 工作包分解

### WP1 普通机器人充能

1. [robot.gd](../../../scripts/robot.gd) 新增 `charge_until_elapsed: float = -1.0` 与 `func is_charged() -> bool`（`GameState.elapsed < charge_until_elapsed`）。**时间基准用 `GameState.elapsed`**——它只在 `main._process` 活动分支递增（[main.gd:711-738](../../../scripts/main.gd#L711-L738)），引导/暂停/结算天然冻结（设计 §6"暂停时充能计时也暂停"零成本满足）。
2. tick 间隔计算处（[robot.gd:82-90](../../../scripts/robot.gd#L82-L90)，黏液 ×2 同位）：`if is_charged(): tick_interval *= 0.5`——与升级档位（查表值）相乘即"升级×充能"复乘口径；重复命中 `charge_until_elapsed = max(charge_until_elapsed, elapsed + 6.0)` 刷新不叠倍率。
3. laser_manager.fire 已开格分支：命中格上的 opener/marker（按当时所在格快照）→ 每台每轮一次充能（去重集合）。
4. 视觉：`ChargeRing`（Node2D `_draw` 圆弧按剩余比例，挂机器人节点；FactionMarker 同款 attach 式）；电弧帧素材可后置（Q4）。
5. guard/detector/miner **不吃充能**（设计只承诺作业机器人；guard 开火间隔是 const，决策 Q1 记录）——`is_charged` 判定限定 opener/marker。

### WP2 筑墙工 builder（新敌人实体）

1. 新建 `scripts/enemies/builder.gd`（独立脚本，不塞进 enemy.gd 的 4 型 `_harm`——行为差异大：耐久/施工/不出巢；参照 nest.gd 独立文件先例）+ EnemyManager 注册 `spawn_builder(coord)`。
2. **调度**（elapsed 基准，[enemy_manager.gd `tick`](../../../scripts/enemies/enemy_manager.gd#L50-L72) 加分支）：有效游玩 12s 首只 → 之后每 25s 尝试补 → 场上 ≤2；出现前**裂隙闪烁 2s**（bomb 阴影期先例改时长；裂隙=已开区边缘合法格，闪烁期格上无碰撞）。
3. **耐久与死亡**：`hp = 2`；`take_hit(by_actor)` 每轮≤1（去重集合）；死亡走 `died` 信号进 `_on_enemy_died`（138-149）加 builder 分支：+10 分（combat_score）/+5 金（player_combat 或 guard_combat 按来源）+受击/死亡反馈（耐久 2→1 显示裂纹态）。
4. **移动**：在已开安全区内低速游走（`ENEMY_MOVE_SEC` 量级；路径 [pathfinding.gd](../../../scripts/pathfinding.gd) 已开格限制），不进未开格、不占基地/机器人当前格。
5. **不做的**：不偷分、不扣命、不改 `is_opened`/数字/钻石位（总纲 §7 底线）——builder 脚本不持有任何 cell 写入权，唯一写入走 WP3 的 `place_cover_wall` 单入口。

### WP3 覆盖墙（敌造动态墙）

1. [cell.gd](../../../scripts/cell.gd) 新增 `cover_wall_hp: int = 0` + `place_cover_wall(hp)` / `damage_cover_wall(n) -> int`；只在**已开安全格**合法。
2. 视觉：半透明墙体覆盖 + **原数字淡显**（总纲 §4.7 建议；refresh_visual 分支，与 web 遮罩同层不同样式，命名 `CoverWallOverlay` 避免与障碍 mark 误匹配）；耐久 3（2-3 起）加裂纹角标（复用 WP2-1 裂纹素材）。
3. **通行**：`is_walkable`（[grid.gd:700-705](../../../scripts/grid.gd#L700-L705)）加 `cover_wall_hp <= 0`——覆盖墙阻挡机器人与 builder；不挡激光（激光照常穿并削层）。
4. **施工规则**（`place_cover_wall` 入口校验，设计 §6 逐条）：每只每 6s 一块；候选=自身周围 2 格已开安全地面，**优先最近 10s 被玩家激光拆过的地面**（laser_manager 维护 `recent_laser_opened: Dictionary` coord→elapsed，环形淘汰）——laser_manager 在 WP1 充能同批把"激光造成开格/拆墙"的坐标记入；排除旗格/已转化资源/基地/机器人当前格/裂隙/既有覆盖墙；每只≤4、全场≤8；**出口保活**：候选放置后从基地 BFS 已开格（视候选为阻挡）须仍能到达任一与未开格相邻的格，否则弃本次；无合法格跳过不报错。
5. **拆墙结算**：`damage_cover_wall` 归零 → +1 分（新 source `cover_wall`）+1 金 + 跳字；底层已开格**不重复**发开格奖励（`rewarded_flags`/首开口径天然防重，总纲 §8.1）。
6. **开墙机器人接手**：opener 工作目标扩展——Solver 无事时，找可达范围内（相邻）的已知安全覆盖墙 `damage_cover_wall(1, "robot_opener")` 每工作 tick 削 1 层（"预先知道安全的动态覆盖墙"=已开格上的墙，无推理需求，设计 §5）；优先级低于正常开格任务。
7. **清场**：`enemy_manager.clear()`（124）连带清 builder 与覆盖墙（cell 随 `init_empty_grid` 重建自然归零，builder 实体显式 free）。

### WP4 激光对敌与护卫

1. laser_manager.fire 快照扩展：束穿格上有 builder → 每轮 1 伤（去重）；命中反馈=耐久角标跳动+受击音（可复用现有命中语言）。
2. **laser_mode 下的点杀旁路**：[main.gd `_try_hit_enemy_at`](../../../scripts/main.gd#L874-L923) 在 laser_mode 分流——点击敌所在格=照常发射激光（束终点即该格必命中），不再走 1 CD 即杀（Q2 决策记录：保留函数与领土规则给 ch01，ch02 全走射线）。
3. 护卫：索敌优先级表头插 builder（[guard_robot.gd:92-125](../../../scripts/robots/guard_robot.gd#L92-L125)）；开火杀 builder 走 `_on_enemy_died` 同一结算（+10/+5，guard_combat）。护栏在 ch02 的可用性：`shop_extra=["guard"]` + `allowed_modules` 加 "guard"（WP5）。

## 4. 实施顺序与里程碑

```
M1 充能可见 ──── WP1（随机盘验证 ×2 手感与冻结）
M2 敌人循环 ──── WP2 builder → WP3 覆盖墙（施工/拆除/保活闭环）
M3 对敌闭环 ──── WP4 激光伤敌+护栏 → WP5 关卡接线
M4 内容与验收 ── WP6 烘焙 → WP7 director+实测
```

- M1 验收：一枪同时拆墙+充能；暂停/引导期间充能环不走。
- M2 验收：12s 首敌→施工→玩家拆墙得分→机器人接手拆墙全链；放任 60s 墙不过上限、基地可达。
- M3 验收：两枪杀一只；护栏路线可通关。
- M4 验收：三路线（持续拆墙/优先杀敌/买护卫专注标记）模拟都不软锁；六断言过。

## 6. 决策记录与待定问题

- **Q1 guard/detector 不吃充能**（已定，本计划口径）：设计只承诺"开墙、标记等既有作业机器人"；guard 开火间隔为 const（注释明示不吃升级轨），单开充能特例成本>收益。若实测护卫太弱再议。
- **Q2 laser_mode 下点杀入口旁路**（已定）：ch02 玩家武器统一为激光，点击敌=射击该格；`_try_hit_enemy_at` 保留给 ch01。
- **Q3 覆盖墙阻挡通行**（已定）：语义是"墙"；机器人拆除是唯一通路恢复方式（玩家激光亦可）。若实测堵路挫败感强，备选=不挡 marker 只挡 opener。
- **Q4 电弧素材**：先 `_draw` 充能环+微闪（零素材），电弧帧列 WP9-式后置批。
- **Q5 动态分容错**：220-232 静态差仅 12 分内必补动态——若模拟发现"必须放任敌人刷墙才能过"则调目标分/补墙速率（设计 §7 明示不做成必放敌关），不取消标记步骤。

## 7. 调研依据

- **buff 管线**：本项目黏液减速（[robot.gd:88-90](../../../scripts/robot.gd#L88-L90) 乘法位）与玩家 CD 恢复乘数（[game_state.gd:244-245](../../../scripts/autoload/game_state.gd#L244-L245)）双先例——"查表值后乘临时系数"是既定引擎口径；RTS 增益（SC2 兴奋剂类）与设计稿 §10 FFF-422 主束附带效果同构。
- **敌造障碍**：本项目 web/lock 的"已开格叠可清除态"路径（[cell.gd:400-448](../../../scripts/cell.gd#L400-L448)）直接复用为覆盖墙载体；Candy Crush 巧克力增长=设计稿已引的"可管理增长"参照。
- 新敌不引入新结算体系：走 `_on_enemy_died` 单入口（player/guard 分列埋点沿用）。
