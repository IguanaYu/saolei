## 3. 工作包分解

### WP1 引光柱实体（耐久与恢复）

1. `scripts/facilities/light_pillar.gd`（FacilityManager 子实体）：`hp: int = 6`、`last_hit_elapsed: float`、`is_alive`；程序绘制本体+**耐久条**（单条，不做第二套计量——设计 §4）。
2. **恢复计时**：`facility_manager.tick(delta)` 由 main._process 统一驱动（挂在 [main.gd:736-738](../../../scripts/main.gd#L736-L738) robot/enemy/boss tick 之后）——继承三重门（game_active/paused/tutorial 早退在 _process 头部，自动冻结）；逻辑：`elapsed >= last_hit + 6` 后每满 3s `hp = min(6, hp+1)`（首次恢复=受击后第 9 秒，设计 §4 精确口径）。
3. **受击**：`take_hit() -> bool`（返回是否致命）：柱本轮已被扣过则拒（去重集合）；hp==0 → `is_alive=false` 破碎演出；**同一次射击不能既打破又恢复**（结算与 tick 不同帧，天然成立，断言进实测）。
4. **视觉态**：hp≤2 变色（暖橙→暗红预警）；恢复时缺口逐格亮起；破碎=碎块淡出+「-50」大跳字。
5. **占格**：柱格不可走/不可放折光/敌不施工不攻击（2-2/2-3/2-4 排除表加"柱格"）；**右键不可标**（已开格本就不可标，断言兜底——设计 §7"不能被右键标记成免伤对象"）。

### WP2 强制定向（几何改写）

`compute_shot_geometry` 快照阶段加定向分支（**以射击开始的柱存活态为准**——设计 §7"破碎的方向变化从下一轮生效"，快照固化天然满足）：

1. 主束命中折光时：若柱存活 → 出射主轴 = `beam_cells(折光格, 柱格)` 的方向与线段（**不受 6 长限制，终止于柱**）：
   - wide：该完整线段的 3 宽走廊（垂直 ±1 两条平行超覆盖线，全长）；
   - scatter：中束=折光→柱线段；左右侧束=柱轴 octant ± 1 方向、**各长 6**（设计 §3 第 2 条）；
   - 柱格必在命中集内（轴到柱终止）→ 每轮增幅必实际消耗柱耐久。
2. 柱不存活 → 沿用 2-3 入射方向规则（零改动路径）。
3. **柱受击来源汇总**（同轮去重后合计扣 1）：增幅轴命中 / 玩家直射束穿柱格 / 爆炸 3×3 波及——全部走 `take_hit()` 单入口；敌人不攻击（builder 无对柱行为，WP1 排除表）。
4. 预览同步：预览画出定向主轴与"本次将命中柱"标识；柱 hp≤2 时预览束段变暗红、hp==1 时线上弹出文案「本次命中将破碎，-50 分」（设计 §4"射前理解代价"）。

### WP3 破碎结算与达标时序

1. laser_manager.fire 结算序最终形态：① 快照（含定向）→ ② 逐格结算（束/爆炸/充能/对敌/节点/削层/碎钻）→ ③ **柱致命判定**：`take_hit` 返回致命 → `add_score(-50, "pillar")`（钳 0，2-1 预埋）→ ④ `_update_objective_progress()` 达标判定。**350 分 +20 破柱 = 320 不判胜**（设计 §7 数例入实测）。
2. 破柱后续：折光恢复入射方向（下一轮快照生效）、不退金币、不撤标记、已开格保留、关卡继续（REACH_SCORE 未达照常推进）；破柱不结束游戏、不触发失败动画。
3. 结算行：results/score 面板 ch02 分支加「引光柱」行（-50 一次性、零值收起）；埋点加 `pillar_hits / pillar_broken / pillar_lowest_hp`（总纲 §11 观察项）。
4. director 句「引光柱破碎，损失 50 分。」由 `pillar_broken` 事件触发（若发生）。

### WP5 固定盘烘焙 ch02_s5

`tmp/ch02_s5_board_finder.py`（finder 加柱定向几何与恢复计时模拟）。断言设计 §5：① 折光→柱主轴穿可反复处理的工作面、敌可在其中合法补墙（定向有实际收益）；② 基地→折光入射线清晰，且存在**避开折光与柱**的直射路线（等待期有事可做）；③ 预设宽束驻点与散射候选驻点方向不同、都能连到柱；④ 三节点链完整可预览，至少一个候选射击波及柱（明确取舍位），另有无伤柱普通路线；⑤ 柱不堵基地出口、不挡必要数字；⑥ 静态 300+动态 60（破柱另补）可达性验算：模拟"留敌刷墙"与"正常买护卫"两路线均 ≥360（240s 内 ≤10 只敌=100 分容量口径，总纲 §8.3）。

## 4. 实施顺序与里程碑

```
M1 柱实体 ──── WP1 耐久/恢复/占格（随机盘摆柱验证计时冻结）
M2 定向闭环 ─── WP2 几何改写+预览预警 → WP3 破碎结算序（随机盘全链）
M3 内容与验收 ── WP4 接线 → WP5 烘焙 → WP6 director+全章集成
```

- M1 验收：柱上耐久条/恢复进度/变色三态正确；暂停与引导期间恢复不走。
- M2 验收：定向必中柱、普通直射不受影响；破柱数例（350+20-50）通过。
- M3 验收：六断言过；三行为对比（连发增幅/等恢复穿插/纯直射+机器人）埋点数据可回收；全章连跑+打包冒烟绿。

## 5. 回归清单

1. ch01 七关全量 + ch02_s01–s04 逐关（无柱关 ShotGeometry 定向分支不触发，行为等价断言）。
2. 柱与既有机制交叉：爆炸波及扣耐久但节点不因柱改变链；builder 不占柱格；折光不可放柱格。
3. 结算边界：破柱轮内同时达标/同时误打/同时击杀的顺序（-50 在最后奖励之后、达标判定之前）。
4. 清场：柱/耐久条/恢复计时器/FacilityManager 重开零残留；继续挑战模式下柱状态保留（`continue_mode` 不重置盘面——柱是盘面设施，随局存活）。
5. 打包：export 过滤规则对新目录无意外收编（laser/facilities 是 scripts 子目录，自动入包）。
