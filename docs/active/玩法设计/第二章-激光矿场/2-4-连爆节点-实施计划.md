## 3. 工作包分解

### WP1 FacilityManager 与节点实体

1. 新建 `scripts/facilities/facility_manager.gd`（Node2D，BoardRoot 子节点，Main.tscn 显式命名 `FacilityManager`）——统一管本章静态中立设施（连爆节点 + 2-5 引光柱；折光仍归 robot_manager，它是"机器人"）。**三条链照抄惯例**：清理链（[main.gd `_start_level_with`](../../../scripts/main.gd#L326-L328) 加 `facility_manager.clear()`）、窗口重排 `reproject_all`（[robot_manager.gd:83-86](../../../scripts/robot_manager.gd#L83-L86) 式）、高塔滚动 `on_grid_relaid`（[boss_manager.gd:505-519](../../../scripts/boss/boss_manager.gd#L505-L519) 式；2-1–2-3 无高塔但链先接好，ch02 不上高塔也防窗口缩放错位——`_relayout_play_area` [main.gd:459-470](../../../scripts/main.gd#L459-L470) 实测）。
2. `scripts/facilities/chain_node.gd`（Node2D 实体）：状态 `consumed: bool`；`trigger()` 消耗（视觉收缩闪光帧）并返回 3×3 格集（`grid` 八邻+自身，边界裁切）；程序绘制占位（同心环"爆"字图腾）→ 素材批后补。
3. **占格规则**：节点格——不可走（`is_walkable` 加门，同覆盖墙口径）、折光不可放（2-3 排除表）、builder 不施工（2-2 排除表）、**opener 不拆**（工作目标过滤：节点格不进任何"墙"目标集；它也不是 Cell 态，天然不进 Solver）、玩家右键无效（已开格本就不可标）、激光**可穿**（命中即触发，不阻断后方——总纲 §6.3"被激光命中后立即消耗"）。
4. LevelData 新字段 `chain_nodes: Array[Vector2i]`；`_start_level_with` 装载（仿 pests→enemy_manager.setup_board 的 351-352 接线）。

### WP2 链式触发结算

laser_manager.fire 扩展（仍在快照框架内）：

1. **快照阶段**：束（主+副）命中集里含未消耗节点 → 入触发队列；**BFS 展开**：队首节点 3×3 格集并入本轮命中集（走同一去重：格层已削过则跳过、敌已伤过则跳过），范围内未消耗节点若本轮未触发过则入队——**整条链在快照阶段全部展开**，与束格合并成一个总命中集后才进逐格结算（设计 2-4 §6"连爆顺序用于表现，不能在节点动画间插入新结算"——逻辑瞬时，表现后置）。
2. **结算阶段**：总命中集逐格走现有分支（削层/开格/碎钻/对敌），**充能例外**：充能只认"束格"（主/副束原始格集），爆炸格不给充能（总纲 §6.3）——ShotGeometry 里束格集与爆炸格集分字段携带。
3. **节点消耗**：触发的节点全部置 consumed（同轮去重=触发标记在快照 BFS 已保证一次）；消耗节点格变为普通已开格（此后可走可放）。
4. **表现**：`fx_chain_blast(nodes_in_order)`——按 BFS 序 0.06s 错峰收缩闪光+3×3 短亮框（错峰节拍参照 chord 0.025s 与 reveal_wave）；奖励跳字只在真实开格/拆墙/击杀时出现（设计 §5"节点自身 0 分"）。

### WP3 预览整链

LaserPreview 扩展：悬停束经过任一未消耗节点 → 预览格集=束格 ∪ 该节点可触发的整条链格集（同一 BFS 公开几何），节点格用专属描边色与普通束格区分（"本次整条链的范围，而不是只画第一座"，设计 §4）。`compute_shot_geometry` 返回值加 `chain_cells` 字段——预览与结算继续共用一个函数。

### WP5 固定盘烘焙 ch02_s04

`tmp/ch02_s4_board_finder.py`（finder 加节点链模拟：束→节点→BFS→格层结算，Python 与 GDScript `compute_shot_geometry` 对拍表扩链式 case）。断言设计 §4：① 第一组 3 座相邻节点（中心互在八邻）、基地可直射首发、周围以可确认安全的 1 层墙为主（看清连爆顺序）；② 第二组近未开工作面、数字可推出需保护的钻石（"先标记再引爆"有准备空间）；③ 两组间不可一链贯通（一次引爆不会无预告清全图）；④ 至少一组邻近敌施工地面（开新面 vs 等聚集的时机选择位）；⑤ 节点全在预开安全格、不泄露未开格内容；⑥ 静态 304<320：≥16 分动态可得性验算。

### WP6 ch02_s4 director + 回归实测

1. `scripts/ch02_s4_director.gd` 剧本（设计 §5）：开局「击中节点，相邻节点连爆。」→ 首次引爆（`chain_triggered`，节点闪光自解释）→ 第二组进入注意范围「先标记，再引爆。」→ 误打低收益句沿用 2-1 文案不新写。
2. 实测 `tmp/auto_laser_s4_test.gd`：第一组三座连续触发、第二组不被第一组无预览引爆（预览含整链）；直射/宽束/散射启动节点规则一致；重叠爆炸单格只削 1 层（三座紧邻三层墙一轮仍剩层——设计 §3"三层墙不能靠紧挨三座节点一轮炸开"）；节点同轮只触发一次（销毁动画未结束不重复爆）；旗格与已转化资源在爆炸中保留；节点耗尽后普通流程继续可玩（不软锁）；边角节点范围裁切与预览一致；重开清场（FacilityManager.clear + 窗口缩放重投影）。
3. 回归：ch01 + 2-1/2-2/2-3（无节点关 ShotGeometry.chain_cells 恒空，行为等价断言）。

## 4. 实施顺序与里程碑

```
M1 设施层 ──── WP1 FacilityManager+节点实体（占格/三链接线）
M2 链结算 ──── WP2 快照BFS+结算扩展 → WP3 预览整链（随机盘摆节点跑通）

```

- M1 验收：节点摆上盘不可走/不可放/敌不施工/机器人不拆。

- M3 验收：六断言过；"急着开地面 vs 先标记"两条模拟路线都成立。

## 6. 决策记录与待定问题

- **Q1 节点"被激光命中即消耗"与穿透**（已定）：命中格入集、节点消耗、束继续穿后方（不阻断）——同旗格"保护不阻断"的镜像语义，入单测。
- **Q2 消耗后空格可放折光**（已定）：节点是一次性设施，消耗后格恢复普通——为 2-5"折光驻点选择"留空间。
- **Q3 表现节拍**：BFS 序错峰 0.06s（快于 chord 0.025s×N 的体感上限待调）——长链（≥5）总时长封顶 0.4s，超出改并发闪光。实测调。
- **Q4 敌施工排除"裂隙格"已有**（2-2），节点格同理入排除表——零决策成本，列此防漏。
