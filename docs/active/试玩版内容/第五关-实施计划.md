## 3. 工作包分解

### WP1 目标类型 + 关卡覆写 + 固定盘（地基，先做"没有招式的安静 Boss 关"）

**目标**：进 L5 = 固定 14×14 盘 + 180s + 「拔牙 (X/20)」进度行 + 拔完 20 颗牙即胜利（Boss 不出招）。这一步完成后 L5 已是一个可完整通关的普通关，后面每个 WP 只往上叠招式。

1. [objective_data.gd](../../scripts/data/objective_data.gd)：
   - `enum Type` 加 `FIND_ALL_MINES`
   - `build_progress_text()`：`"目标: 拔牙 (%d/%d)"`；`short_label()`：`"拔光 %d 颗牙"`
2. [grid.gd](../../scripts/grid.gd) 新方法 `count_processed_mines() -> int`：遍历雷格，`is_vein or is_confirmed_mine or is_collapsed` 计 1——三种处理方式的**格级状态天然去重**（正确旗即时转矿脉无从撤起；确认雷永久；坍塌不可逆），不需要独立计数器
3. [main.gd:911](../../scripts/main.gd#L911) `_update_objective_progress()` 加 match 分支：`current = grid.count_processed_mines()`、`total = grid.mine_count`；达标判定挂进现有 `level_complete` 通道（与 CLEAR_ALL_SAFE 同路径——达标 → 结算 → s05 触发 `playtest_done_requested`）
4. [level_database.gd:54](../../scripts/data/level_database.gd#L54) `_build()` 加 `s_idx==4 → _apply_playtest_level5(lvl)`，参数映射：

| LevelData 字段 | 值 | 说明 |
|---|---|---|
| grid_size / mine_count | 14×14 / 20 | 密度 10.2% |
| fixed_mines + 预开区 | 烘焙产物 | 见第 5 条；`pregen_random` 留 false |
| objectives | **FIND_ALL_MINES**（target_value=20） | 替换默认 SURVIVE_TIME |
| time_limit_sec | 180.0 | |
| start_gold / start_lives | 300 / 3 | meta_progression=true 叠局外 |
| free_clicks / cooldown_sec | 5 / 3.0 | `cd_max_charges` 不设（默认 7） |
| forbidden_actions | **[]**（清掉默认 boss 分支的 `["flag"]`） | 旧 s05 禁标雷废除——本关标雷是主输出口 |
| shop_limits / shop_hidden / shop_extra | {"guard":1} / ["detector","miner","drone","debug"] / ["guard","probe"] | L4 白名单原样 |
| upgrades_hidden / base_price_flat / time_bonus_per_sec | ["discount"] / 80 / 3 | L4 同款 |
| allowed_modules | ["opener","marker","guard"] | L4 同款 |
| no_stars / is_playtest / 首通 200 / 重玩 50 | true / true / 200 / 50 | L4 同款 |

5. **固定盘烘焙**：`tmp/level1_board_finder.py` 换参数（14×14/20 雷/预开 30-40%/2 规则全程可推/开局 ≥5 秒推目标/≥6 格连锁一次），追加两条 Boss 入口约束（设计 §9.6/9.7）：上边中段 6-8 格对应盘内第一行无雷、右边对应列无雷；产出 `fixed_mines` + 预开区烘焙进关卡数据
6. 结算口径自查：`FIND_ALL_MINES` 达标瞬间锁定时间加分（斩杀演出 3s 不吃倒计时，见 Q6）

**验收**：L5 可完整通关：预开固定盘 → 放基地 → 扫雷 → 拔完 20 颗牙（含机器人标旗/探测/踩塌三种来源混合）→ 结算 → 试玩完成页出现；HUD 目标行全程显示 (X/20)；L1-L4 与正式关回归不变。

### WP2 Boss 实体 + 三阶段状态机（不出招的骨架）

**目标**：Boss 站在上侧盘框外缘，随牙数切换阶段姿态与位置；转场演出与出招暂停机制就位——后续 WP 的招式全部由它调度。

1. **新目录** `scripts/boss/`，两文件：
   - `boss_beast.gd`（Node2D，Main 场景树显式命名 `BossBeast`，世界坐标按 grid 边界计算贴上侧盘框）：姿态机 `idle / claw(亮爪) / inhale(吸气) / growl(低吼) / staggered(硬直) / crawl(换位爬行) / fall(斩杀掉落)`；位置锚点 `top / right` 两处；三阶段损伤贴图状态；占位 = 深色巨兽色块 + emoji（正式素材列美术需求，WP8）
   - `boss_manager.gd`（Node2D，显式命名 `BossManager`，与 EnemyManager 平级）：
     - **牙数监听**：`processed_mines_changed` 信号（grid 每次 `become_vein`/`confirm_mine`/`collapse` 后 emit，或 WP1 计数处顺带 emit）→ 对照阈值表 `PHASE_TEETH := [5, 11]` 切阶段
     - **阶段状态机**：`phase: int`（1/2/3）+ 转场流程（演出 2s → 出招暂停 3s → 开放该阶段出招表）；`staggered_until: float`（硬直期所有出招计时冻结）
     - **出招调度骨架**：每阶段一张招式表 `[{"kind":"slime","every":30.0,...}, ...]`（WP3/4/5 逐个填实），统一 tick 驱动（挂 `main._process`，与 enemy_manager 同点——pause 天然停摆）
     - **斩杀流程**：`count_processed_mines() >= mine_count` → 冻结全场（虫/炸弹/触手计时暂停）→ `boss_beast.play("fall")` 3s → 走既有胜利结算通道
2. 转场演出接 EffectsLayer：震屏 + 尘土；P3 转场触发 `crawl`（top → right，2s）
3. Boss 本体**无命中盒**、不可点击（设计 §3：血量即牙数，没有"打本体"）

**验收**：手动拔牙到 5/11/20，Boss 依序换姿态/换位/掉落；转场期间出招计时冻结；暂停时 Boss 计时全停。

### WP3 P1 史莱姆（敌虫系统扩展 + 击杀条件）

**目标**：2 只史莱姆沿未开墙爬行糊黏液；开路接近才能点杀；保安在史莱姆进已开区后接杀；P1 期间每 30s 补至 2 只。

1. [enemy.gd](../../scripts/enemies/enemy.gd) `type` 加 `"slime"` 分支（行为与三虫分道）：
   - **移动**：不走"奔基地"——每步从未开邻格中随机选一（空列表则原地），**偏 frontier**：候选里含"邻 8 格有已开格"的墙格时 70% 优先；步速 2.5s/格（`ENEMY_MOVE_SEC` 改为按 type 查表）
   - **施害**：每步离开时当前格 `apply_slime()`（墙上/开地通吃，`is_slimed` 状态本就不区分开合——黏液语义统一）
   - 无 lurk、无基地目标；爬进已开地面后继续同款随机游走（保安的"虫进已开区才可射杀"自动生效）
2. [enemy_manager.gd](../../scripts/enemies/enemy_manager.gd)：
   - `waves_enabled: bool = true` 字段（L4 不动；L5 由 main 按 LevelData 置 false——**否则 L4 三虫波次会在 L5 误放**，§1.2 缺口）
   - `spawn_slime(at: Vector2i)` 薄封装：调既有 `spawn_enemy(at, "slime", grid)`
3. BossManager P1 出招表：`t=15s/18s` 各 1 只（入口 = Boss 盘框侧盘边随机墙格）；此后每 30s 若场上 `"slime"` 数 <2 且 phase==1 → 补至 2；**phase ≥2 后不再补充**（残兵自然带入）
4. **击杀条件**（设计 §5.1）：[main.gd:620](../../scripts/main.gd#L620) `_try_hit_enemy_at()` 史莱姆分支加前置判定——本体格或邻 8 格含已开格才可命中；不满足则**不耗 CD 不命中**（史莱姆视觉双态：可点=常态，不可点=半透明压暗，纯视觉自解释不占文案预算，Q7）
5. 击杀结算：+10 钱 +10 分；`boss_manager.stagger(3.0)`；埋点 `slime_kills += 1`
6. 史莱姆点杀吃 1 层 CD（`consume_player_action()`，与 L4 点虫同口径）

**验收**：两只史莱姆上墙爬行留黏液；远处点击无效且不耗 CD、半透明可辨；开路推进后可点杀；史莱姆爬进开地被保安射杀；杀完后 30s 内 P1 阶段补位；转 P2 后不再补。

### WP4 P2 炸弹 + 火区（本计划最重的 WP）

**目标**：预告 1.2s → 落弹压格（70% 数字格）→ 引信 5s 内点击反弹 / 超时爆成十字火区；火区禁入机器人、8s 退散、点击整片灭、烧黏液。

1. **落点选择器**（BossManager 内）：候选 = 全部已开格 − 排除表（基地格/任何机器人当前格/火区内/已有炸弹格/触手格）；70% 概率从"数字格且未被网/炸弹遮罩"子池优先（无合格数字格则全池）；已开格总数 <8 → 本次出招顺延 10s（设计 §7 边界）
2. **新文件** `scripts/boss/bomb.gd`（Node2D，`z_index` 高于 Cell，与史莱姆同层）：
   - 状态机 `shadow(1.2s 阴影预告) → fuse(5s 引信，火花+读条) → deflect | explode`
   - `deflect()`：飞向 Boss 本体（EffectsLayer 位移 tween）→ 硬直 2s + 该阶段炸弹出招计时 +7s → +15 钱 +15 分 → 埋点 `bombs_deflected += 1`
   - `explode()`：以落点为中心的十字 5 格（越界裁剪）→ 逐格 `ignite_fire()`
   - 视觉与棋盘地雷强区分（设计 §5.2）：黑铁壳 + 燃烧引信 + 落点阴影，占位 = 深色圆 + 火花 emoji（WP8）
3. **Cell 新状态 `is_on_fire`**（[cell.gd](../../scripts/cell.gd)）：
   - `ignite_fire(duration)` / `fire_out()`；火由 BossManager 统一倒计时（`fire_cells: Dictionary[coord → remaining]`，tick 里递减，归零 `fire_out()`）
   - **通路阻断**：Cell 加 `path_blockers: int`（火 +1/−1；WP5 触手同用）；[grid.gd:457](../../scripts/grid.gd#L457) `is_walkable()` 追加 `and c.path_blockers == 0`——默认 0 时与现状逐字节等价（回归短路）
   - **震退**：点燃瞬间 [robot_manager.gd](../../scripts/robot_manager.gd) 新方法 `displace_robots_in(coords)`：区内每台机器人瞬移至 BFS 最近的无阻断已开格 + 走路动效（不做飞行轨迹，Q3）
   - **烧黏液**：`ignite_fire()` 时该格 `clear_slime()`（免费组合：火清黏液）
   - **灭火**：点击火区任一格 → **该连通火片区整片熄灭**（BossManager 按 4 向连通分组，设计 §5.2"整片熄灭"）→ 1 层 CD + 5 钱 + 5 分 → 埋点 `fires_extinguished += 1`。实现走格子点击分流：`is_on_fire` 并进 [grid.gd:530](../../scripts/grid.gd#L530) 的 `has_obstacle()` 优先级链（灭火优先于该格开/标）
4. **数字遮罩**：Cell 加 `bomb_masked: bool`（bomb 落格 set / 离开或爆炸 clear）——**不复用 `is_webbed`**（清网交互会误伤）；[solver.gd](../../scripts/solver.gd) 推理源判定处追加 `or cell.bomb_masked`（与 webbed 同一行短路，默认 false 回归不变）；视觉复用网的"数字被盖"口径
5. BossManager P2 出招表：首弹 = 转场后 5s；此后每 18s；同场 ≤2；预告姿态 `inhale`（吸气 1.5s 在 shadow 之前）；P3 降为 35s/≤1（WP5 调表）

**验收**：炸弹按选择器落点、数字格被压后机器人停摆（同网口径）、点击反弹飞向 Boss 且下次出招顺延；放任爆炸成十字火、区内机器人被震退、机器人绕行；点一格整片灭；火盖黏液格则黏液消失；8s 自然退散；暂停时引信/火计时全停。

### WP5 P3 锁链 + 触手 + 换位

**目标**：Boss 爬到右侧盘框；每 25s 抛 3-5 把锁；每 30s 伸一条触手挡通路；炸弹降频。

## 6. 决策记录与待定问题

**已定（随设计 v1.0）**：牙数=血量（三来源格级去重）；阶段阈值 5/11；保安不认新对象；反弹/灭火/断触手/点杀全吃 CD；转场不停表；斩杀即关终无继续挑战。

**实施决策（本文档初值，盲测后校准）**：

- **Q1 史莱姆染黏液口径（初值：每步离格时 `apply_slime()`，墙上开地通吃）**——设计 §5.1"沿途墙体格染黏液"的字面执行；步速 2.5s/格下 60s 约染 24 格，覆盖度由盲测观察（过密 → 改每 2 步染一次）。
- **Q2 史莱姆接近判定的视觉表达（初值：可点=常态、不可点=半透明压暗，不用文字）**——文案预算已满 6 句；若盲测显示玩家不知道"要先开路"，加一次性 UX toast（不占教学文案预算，同 L4"只能放在已开区域"口径）。
- **Q3 震退实现（初值：瞬移至 BFS 最近无阻断已开格 + 走路动效）**——不做飞行轨迹；"被震退"的读法靠动效顺序（爆炸 → 机器人闪现新位置 + 尘土）。
- **Q4 触手段不足 4 格（初值：出招顺延 10s）**——与炸弹"已开格 <8 顺延"同款兜底，保证 P3 永有招可出。
- **Q5 Boss 攻击计时的暂停口径（初值：全部计时由 `main._process` 驱动，pause 天然停）**——与虫/机器人同点驱动，不加独立处理。

## 7. 调研依据

- **敌人攻击可反用（deflect 原型）**：马里奥踩弹飞回、塞尔达盾反——「Boss 的弹药经玩家之手变成伤害」是动作游戏的经典原型，头脑风暴 §6「炸弹人扔回库霸王」同源；本作差异在反弹消耗的是 CD 层而非操作精度（扫雷玩家不是动作玩家）。
- **临时地形阻断的防死锁律**：塔防/RTS 的定时障碍（如 Dota 路障、树精守卫）均以"必自动恢复"为铁律——本关火 8s/触手 12s 全部定时兜底，机器人 BFS 不可达时原地待命沿用现状，无永久死锁路径（设计 §7 承诺的实现面）。
- **点击优先级实现约束**：[godotengine/godot#29825](https://github.com/godotengine/godot/issues/29825)（承 L4 §7）——重叠 CollisionObject2D 全收事件且不阻断传播，实体命中一律走 `main._input` 几何拦截，本关三个新实体沿用该结论。
- **Boss 三阶段「每阶段一件事」**：马里奥系列三段 Boss 的用户基准（头脑风暴 §1 用户拍板）；阶段随进度推进而非纯时间（Dome Keeper 的波次打断挖掘节奏，本作反过来让扫雷进度驱动阶段——「掘即攻」）。
- **内部先例**：L4 敌虫/保安/探测全套子系统（本关地基）；无人机/探测的"花钱瞬发影响盘面"模式（炸弹落点选择器与反弹结算参考）；`tmp/level4_sim.py` 逐 tick 模拟方法（WP9 直接复用）。
