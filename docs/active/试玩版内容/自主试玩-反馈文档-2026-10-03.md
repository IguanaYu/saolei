## 已确认的问题

### F01 · P2 · 游戏树暂停时 Esc 失效，暂停/设置/规则返回受影响

- 路径：第二关 → Esc 打开暂停 → 再按 Esc；另一路径是暂停 → 声音与设置 → Esc。
- 现象：暂停面板明确显示“按 ESC 继续”，实际按键后仍保持暂停；暂停内的设置页连续两次 Esc 也未关闭。点击设置页“返回”和暂停页“继续挖矿”有效。
- 影响：玩家可能以为游戏卡住，键盘返回层级与主菜单设置页的表现不一致；可通过按钮继续，所以没有定为 P1。
- 复现：暂停内设置连续两次 Esc 无效；返回暂停后 Esc 仍无效。主菜单设置的 Esc 已验证有效，可作对照。
- 真实电脑复核：第一关使用真实 Esc 打开暂停，再按 Esc 仍暂停；暂停内设置按 Esc 无效，鼠标返回与继续有效。主菜单设置按 Esc 正常返回；主菜单规则页按 Esc 两次均未关闭，鼠标“返回”有效。新增规则页分支归入同一问题，不重复计为第四个问题。
- 证据：[暂停提示](自主试玩证据-2026-10-03/35-pause.png)、[设置内 Esc 第一次](自主试玩证据-2026-10-03/40-settings-returns-pause.png)、[第二次](自主试玩证据-2026-10-03/41-pause-settings-esc-repeat.png)、[暂停 Esc](自主试玩证据-2026-10-03/43-pause-escape-resume.png)、[按钮恢复](自主试玩证据-2026-10-03/44-resume-button.png)。第 40 张沿用采集时的预期命名，实际画面仍是设置页。
- 原生输入证据：[暂停后 Esc](自主试玩证据-2026-10-03/native-11-escape-cannot-resume.png)、[暂停设置内 Esc](自主试玩证据-2026-10-03/native-13-paused-settings-escape-fails.png)、[鼠标继续](自主试玩证据-2026-10-03/native-15-resume-button.png)、[主菜单设置 Esc 对照](自主试玩证据-2026-10-03/native-20-menu-settings-escape-works.png)、[规则页 Esc 两次后](自主试玩证据-2026-10-03/native-24-rules-escape-repeat.png)。
- 源码线索：Esc 路由集中在 `scripts/main.gd:_input/_handle_escape`；Main 根节点继承默认处理模式，`scenes/Main.tscn` 只给 UILayer 设置了 ALWAYS。`rules_panel.gd:open()` 即使从主菜单打开也会暂停树。树暂停后，Main 的输入路由停止，UILayer 内按钮仍能处理。此线索与两轮操作结果一致，修复后仍需重跑实际输入。
- 建议：让暂停期间可用的 Esc 路由在持续处理的 UI 层运行，并确保只退一层。验收“局内→暂停→恢复”“暂停→设置/规则→暂停→恢复”及“主菜单→规则→主菜单”，避免恢复时误关闭多个面板。

### F02 · P2 · 操作规则仍要求手动放置机器人

- 路径：主菜单 → 操作与规则 → 向下滚动阅读机器人说明；随后第一关按 1 / 点击商店购买机器人。
- 现象：规则写“购买后需放置到棋盘”，实际扣款后机器人自动从基地旁出场，未进入放置模式。第一关开墙型和标雷型均如此。
- 影响：新玩家可能继续寻找落点、以为购买漏了一步，或把随后的棋盘点击误当放置操作。
- 证据：[规则正文](自主试玩证据-2026-10-03/04-rules-bottom.png)、[按 1 后自动出场](自主试玩证据-2026-10-03/22-level1-buy-opener.png)、[标雷型自动出场](自主试玩证据-2026-10-03/25-marker-and-robots.png)。
- 源码线索：`scripts/main.gd` 的直购直出实现说明机器人已不再手动放置；规则页文案仍沿用旧流程。
- 真实电脑复核：[滚轮后的规则正文](自主试玩证据-2026-10-03/native-22-rules-scroll.png) 仍是旧说明；[真实键盘按 1](自主试玩证据-2026-10-03/native-09-key1-buy-robot.png) 后扣 50 金、机器人直接从基地旁出现。
- 建议：统一改为“购买后从基地旁自动出场”，单独说明基地和探测才需要选择位置；检查试玩测试手册与其他现存说明是否也残留旧操作。

### F03 · P2 · 事件日志容量淘汰时报错，机器人作业栏停止更新

- 路径：第五关放基地 → 买开墙型、标雷型、保安 → 正常运行并使用两次探测 → 机器人作业事件持续累积。
- 现象：本局约 2:28 后，右侧作业栏最新内容停在旧时间。继续运行时金币从 24 变 28、分数从 104 变 108、剩余时间从 0:52 变 0:37，作业栏仍停在 2:28。游戏和结算继续运行，侧栏没有跟上。
- 后端实证：`runtime-engine-input-03.log` 共出现 **41 次** `SCRIPT ERROR: Invalid call. Nonexistent function 'remove_line' in base 'RichTextLabel'.`，均指向 `scripts/ui/event_log_panel.gd:38`。调用来源包括开格合并、空闲轮询、保安清障与结算事件。
- 复现程度：同一局中连续两个观察窗口都产生该错误（首次观察 11 次，继续运行后累计 21 次，结算时累计 41 次）。未另开一局重复达到阈值。
- 源码线索：`MAX_ENTRIES = 120`；`_entries.size() > MAX_ENTRIES` 时执行 `_log.remove_line(0)`，异常使后面的 `append_text()` 和重绘兜底都无法执行。“超过 120 条”为代码条件，未直接读取运行时内部数组计数。
- 证据：[首次停止更新](自主试玩证据-2026-10-03/99-boss-pause-again.png)、[继续运行后的旧作业栏](自主试玩证据-2026-10-03/100-boss-log-overflow-running.png)、[完整运行日志](自主试玩证据-2026-10-03/runtime-engine-input-03.log)（首次错误第 228 行，后续持续重复）。
- 建议：改用当前引擎支持的段落删除接口，或在淘汰旧记录时整体重绘。Godot 4.6 的 [RichTextLabel 官方 API](https://docs.godotengine.org/en/4.6/classes/class_richtextlabel.html#class-richtextlabel-method-remove-paragraph) 提供 `remove_paragraph()`，替换后仍需确认换行和段落索引行为。
- 验收：两个侧栏分别持续产生超过 120 条事件，检查第 121 条及后续能追加、最旧记录被淘汰、滚动仍可用；让同一局继续到结算，运行日志不再报此错误。
