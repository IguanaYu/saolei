## 3. 工作包分解

### WP1 随机盘装载 + 基地自放（§9.6/§9.7）

**目标**：L4 进关流程 = 预生成随机盘（雷+洪水预开，无基地）→ placing_base 阶段（仅已开格）→ 放完基地开局。与现有"放基地时才生成雷"流程并存不互踩。

1. [level_data.gd](../../scripts/data/level_data.gd) 新字段：
   - `pregen_random: bool = false`（true = 进关预生成随机盘，走新路径）
   - `shop_extra: Array = []`（本关**额外显示**的商店项："guard"/"probe"，默认两者隐藏，见 WP6）
2. [grid.gd](../../scripts/grid.gd) 新方法 `apply_random_board()`：
   - `MapGenerator.generate_excluding(rows, cols, mine_count, [])` 布 40 雷（排除区为空）；
   - 起点选择：随机取一个**非雷且数字为 0** 的格（保证有洪水连锁；无 0 格则任取非雷格）；
   - 洪水预开：从起点做与 [_flood_open](../../scripts/grid.gd#L322) 同构的连通展开，但**直接设 `is_opened` 不 emit 信号**（不给奖励，同 [apply_fixed_board](../../scripts/grid.gd#L143) 的预开写法）；
   - **不预置基地**：`game_phase` 保持 `placing_base`；
   - **裂缝与预置虫害的放置不在此处**（归 EnemyManager，WP3.4，放置时机 = 进关后、放基地前可见）。
3. [grid.gd:112](../../scripts/grid.gd#L112) `place_first_base()` 加分支：新增 `var board_generated := false` 成员，`apply_random_board()` 置 true → 分支内**跳过布雷与安全区预开**，只做三件事：校验该格 `is_opened`（不满足返回 false，HUD 已有 toast 通道可提示"只能放在已开区域"）、`become_base()`、`register_base()` + `set_game_phase("playing")`。
4. [main.gd:192-204](../../scripts/main.gd#L192-L204) `_start_level_with()`：`lvl.pregen_random` 分支调 `grid.apply_random_board()`，**不设** `game_active = true`（放完基地才激活，波次计时随之从放基地起算——`main._process` 的 elapsed 只在 active 后累计，天然满足）。
5. [level_database.gd](../../scripts/data/level_database.gd) `_build()` 加分支 `ch_idx==0 and s_idx==3 → _apply_playtest_level4(lvl)`，参数映射：

| objectives | **CLEAR_ALL_SAFE** | s_idx==3 默认生成就是它，仍显式覆写防回归 |
| pregen_random | **true** | 本关核心开关；fixed_mines 留空 |
| time_limit_sec | 150.0 | |

| shop_limits | **{"guard": 1}** | 保安限购 1 |
| shop_hidden | ["detector","miner","drone","debug"] | |

| upgrades_hidden | ["discount"] | |

### WP2 格子三状态：网/锁/黏液（§9.2，铁律实现）

**目标**：三个独立状态位，与雷位数字真值完全解耦（设计 §5 合规：网=显示遮罩、锁=交互阻断位掩码、黏液=速度修正）。

1. [cell.gd](../../scripts/cell.gd) 新字段 + 状态操作：
   - `is_webbed / is_locked / is_slimed: bool = false`
   - `apply_web()` / `apply_lock()` / `apply_slime()`（幂等：已有同类状态返回 false）；`clear_web()` / `clear_lock()` / `clear_slime()`（清除方=玩家/保安共用入口，emit 新信号 `cell_obstacle_cleared(cell, kind, by_actor)` 供埋点）
   - `has_obstacle() -> bool`（点击分流用）
   - `refresh_visual()`：已开数字格被网盖 → 显示网图标/遮罩层（**数字被盖住，玩家同样看不见**——设计 §5"网=显示层遮罩"）；锁 → 未开岩壁上叠锁图标；黏液 → 叠绿色黏液覆盖（不改变开/旗表现）。三个覆盖用 `TextureRect` 显式命名（`WebOverlay`/`LockOverlay`/`SlimeOverlay`），避免 get_children 误匹配（CLAUDE.md 命名守则）
2. **交互阻断**：[cell.gd:208](../../scripts/cell.gd#L208) `open()` 与 [cell.gd:240](../../scripts/cell.gd#L240) `toggle_flag()` 开头加 `if is_locked: return false`（谁都不能开/标；已插旗格被锁则连撤旗也阻断，见 §6-Q8）
3. **点击分流**（吃 CD，设计 §9.9）：[grid.gd:344-358](../../scripts/grid.gd#L344-L358) `_on_cell_left_clicked()` 在开格判定**之前**插入：
   ```
   if cell.has_obstacle():  # 锁(未开)/网(已开)/黏液(任意)
       if 清除成功(cell.clear_*()):
           GameState.consume_player_action()
           play_player_action_visual(cell.coord, FLY_ICON_OPEN)
       return  # 本击只清障，不开格
   ```
   右键同理：锁格右键也走清锁（锁同时拦开与标，清除是唯一出路）。黏液格：**左键清黏液优先于开格**（设计 §5：黏液不阻断开/标，但点击命中的是障碍——按 §9.9 命中盒优先级，先清后开，玩家第二击再开格）。
4. **Solver 兼容**（[solver.gd:7-40](../../scripts/solver.gd#L7-L40)，三处判定全部短路默认值，旧关零行为变化）：
   - 推理源：`if not cell.is_opened or cell.is_collapsed or cell.is_webbed or cell.adjacent_mines == 0: continue`（**网盖的数字格不再提供依据 → 机器人失明停摆**）
   - 动作目标：open/flag 动作生成处跳过 `n.is_locked` 的目标格（锁格谁都不能动，机器人不锁死目标）
   - `n.is_flagged` 计雷处扩为 `n.is_flagged or n.is_confirmed_mine`（WP5 落地时加，确认雷视同旗）
5. **黏液减速**：[robot.gd:80-85](../../scripts/robot.gd#L80-L85) `accumulate_and_maybe_tick()`：`tick_interval` 计算后追加 `if grid.is_slime_nearby(coord): tick_interval *= 2.0`（含 L3 节奏分离后的移动/工作双间隔——对"下一 tick 将做什么"的那个间隔统一 ×2）。[grid.gd](../../scripts/grid.gd) 新增 `is_slime_nearby(coord) -> bool`：3×3 内任一格 `is_slimed`。**不叠乘**：布尔判定天然 ×2 封顶（设计 §3）。
6. 虫死不回收障碍：障碍清除只走第 3 条的显式入口，与虫实例无引用关系，天然满足。

**验收**：三状态默认 false 时 L1/L2/L3 逐 tick 行为不变（Solver/robot 改动全部短路）；锁格玩家与机器人双双不可开/标；网格数字玩家不可见且机器人停摆；黏液 3×3 内机器人肉眼变慢、出圈恢复。

### WP3 敌虫系统：虫实体 + 巢 + 波次（§9.1/§9.3/§9.8 前半）

**目标**：三虫从巢爬向最近基地、途中定时施害、玩家点杀/保安击杀；巢 HP 2 点击摧毁、毁则该巢波次取消。

1. **新文件** `scripts/enemies/enemy_manager.gd`（Node2D，场景树挂 `Main` 下，与 RobotManager 平级、显式命名 `EnemyManager`）：
   - 波次常量（初值，盲测校准项）：`WAVES := [{t:35.0,type:"web"},{t:75.0,type:"lock"},{t:110.0,type:"slow"}]`、`ENEMY_MOVE_SEC := 2.0`（虫速 ~2s/格）、`HARM_INTERVAL := 8.0`、`NEST_HP := 2`、`PRESET_WEBS := 3`、`PRESET_LOCKS := 3`
   - `setup_board(grid)`：进关时调用——盘边随机两条不同边各放 1 巢（避开盘角，格坐标取边上一格）；预置网 ×3（随机已开数字格）+ 锁 ×3（随机 frontier 关闭格 = 预开区 8 邻中的未开格）；两巢与预置障碍**进关即可见**（放基地前，剧本 #0）
   - `tick(delta, grid)`：由 `main._process` 驱动（与 robot_manager 同点调用，pause 天然停摆）；波次到点 → 从随机存活巢 spawn 虫；驱动所有虫/巢的计时
   - 波次联动：出虫时巢已毁 → 该波取消（双巢皆毁 = 再无新虫，场上已有障碍不回收）
2. **新文件** `scripts/enemies/enemy.gd`（Node2D + 自绘/贴图，z_index 高于 Cell）：
   - `enemy_type: String`（"web"/"lock"/"slow"），HP 1（点杀即死）
   - 状态机：`to_base`（BFS 直奔最近基地，**不受 walkable 限制**——虫爬岩壁；路径用无限制 BFS，新增 `Pathfinding.find_path_free(grid, start, goal)` 静态方法，与现有 [find_nearest_target](../../scripts/pathfinding.gd#L17) 并列）→ 到达基地后 `lurk`（围绕基地 3×3 随机徘徊，**不攻击基地**，§6-Q1 初值）
   - 施害：每 `HARM_INTERVAL` 秒一次——织网虫：当前位置 8 邻+自身中第一个"已开数字格"盖网；锁匠虫：第一个"未开未旗格"上锁；减速虫：当前格直接留黏液。找不到合格目标则本次跳过（施害目标选择规则是执行细节，§6-Q4）
   - 虫被点杀/被保安射杀：`die(by_actor)` → 播放死亡动效 → 从 manager 移除；**已施放的障碍不回收**
3. **新文件** `scripts/enemies/nest.gd`（Node2D + 命中区域）：`hp: int = 2`；玩家点击 → HP-1（吃 1 次 CD）+ 受击动效；HP 0 → 摧毁动效 + manager 标记该巢失效 + 埋点 `nest_cleared_elapsed`。视觉：裂缝占位（代码绘制/现有素材，正式素材列美术生产需求，§6-Q5）
4. **点击优先级**（§9.9，实现方案有硬约束）：
   - **Godot 重叠 Area2D 会全部收到 input_event 且 `set_input_as_handled()` 不阻断传播**（[godotengine/godot#29825](https://github.com/godotengine/godot/issues/29825)，底层 Cell 还先收到）→ 虫/巢**不走 Area2D input_event**，改在 [main.gd:344](../../scripts/main.gd#L344) `_input()` 最前面做**几何命中**：遍历活虫+活巢，点击位置距实体中心 < 0.6 格即命中 → 处理（点杀/打巢，CD 检查与 `consume_player_action()` 同格子点击口径）→ `get_viewport().set_input_as_handled()` → Cell 拾取不再发生。命中测试在 `_in_game()` 与非 placing_base 前置判断之后、格子点击之前
5. 场景文件：`scenes/Enemy.tscn` / `scenes/Nest.tscn`（对齐 Robot.tscn 模式）；虫视觉无贴图时用色块+emoji 兜底（[robot.gd:69-77](../../scripts/robot.gd#L69-L77) 同款模式）
6. 生命周期：结算/放弃/重开时 `enemy_manager.clear()`；`apply_random_board` 后重新 `setup_board`

**验收**：35s/75s/110s 三虫依序从存活巢爬出直奔基地；途中 8s 一害；点虫 1 CD 击杀、巢 2 CD 摧毁；双巢毁后无新虫但场上障碍需手清；暂停时虫停走。

### WP4 保安机器人（§9.4）

## 5. 回归清单

1. **L1/L2/L3 全流程**：Cell 新增四状态默认 false——Solver/robot/交互的每一处新判定必须短路（重点回归：L1 教学剧本 5 句、L2 升级考题、L3 过线+继续挑战）；upgrade/shop 参数化不因 guard/probe 分支破坏旧关（旧关两按钮不可见）。
2. **随机路径不互踩**：普通关（旧 place_first_base 布雷流程）、固定盘关（apply_fixed_board）、L4（apply_random_board）三条进关路径并存——旧关与 L1-L3 行为逐项不变。

4. **暂停与结算边界**：暂停时虫/保安/波次计时全停（统一由 `_process` 驱动）；到点/命尽强停时虫害清理无残留；重开新盘（`setup_board` 重置）；放弃流程无双重发矿。

## 6. 决策记录与待定问题

**已定（随设计 v2.1）**：三虫同关（减速虫属 L4）；保安仅已开区巡逻；裸随机不设生成时过滤；虫害三层不碰真值；虫死不回收障碍；保安 80 限购 1；探测 100/次不限购。

**实施决策（本文档初值，盲测后校准）**：

- **Q1 虫到基地后行为（初值：原地徘徊继续施害，不攻击基地）**——设计未定义；攻击基地会引入"基地被毁"新失败态，超出试玩版范围。若盲测显示虫到基地后威胁感不足，再议。
- **Q2 保安速度（初值：固定 2.0s/格，不吃升级轨）**——保安是"花钱买断的清道夫"，不参与升级系统便于盲测归因；若体感太慢，改吃 opener 移动轨是一行改动。
- **Q3 探测放置是否吃 CD（初值：不吃）**——与放机器人/建基地同口径（放置类操作均不吃 CD）；若盲测发现探测连点过强再改。
- **Q4 施害目标选择（初值：虫当前位置 8 邻+自身中第一个合格格，找不到跳过本次）**——保证"沿途"语义且实现简单；锁匠优先未开未旗格，避免锁掉玩家已确认的成果。
- **Q5 敌害视觉素材（初值：代码色块/emoji 占位，正式素材列美术生产需求）**——虫×3 种、巢裂缝、保安、确认雷图标、三种障碍覆盖；对齐 robots/ 皮肤生产流程，不阻塞玩法实施。
- **Q6 已插旗格被锁（允许，旗不可撤直到清锁）**——"锁=进度层阻断谁都不能开/标"的字面执行；烈度由盲测观察。
- **Q7 网对玩家同样遮数字（已定：遮）**——设计 §5"显示层遮罩"语义，玩家与机器人同盲，点撕是唯一恢复方式。

**遗留**：

- **Q8 到点/命尽矿石口径（承 L2/L3 Q1）**：仍按 score/10 常量，讨论结果出来改一处。
- **Q9 虫体碰撞体积与点击判定半径（0.6 格初值）**：实机手感项，M2 阶段实测定。

## 7. 调研依据

- **扫雷+敌人的形态先例**：[DemonCrawl](https://dopefishblog.com/2020/08/05/dopefish-reviews-demoncrawl)（Therefore Games）——扫雷 roguelike，雷=怪物、命+防御兜底失误、omens 主动阻碍；印证本关"敌人+命兜底+预置虫害"的结构合理性。其最大批评是 **RNG 过强导致挫败**（[Save or Quit 评测](https://saveorquit.com/2020/05/21/review-demoncrawl)）——正是 L4 §7"裸随机+观察项+探测兜底"要防的风险，WP8 分布断言即离线预警。
- **点击优先级实现约束**：[godotengine/godot#29825](https://github.com/godotengine/godot/issues/29825)——Godot 重叠 CollisionObject2D 全部收到 input_event 且 `set_input_as_handled()` 不阻断传播、底层先收；据此否定"虫用 Area2D 拾取 + Cell 侧让位"方案，改用 `main._input` 几何命中（`_input` 阶段 handled 后物理拾取不再发生）。
- **瞬发情报道具**：本项目内部先例——无人机（100 金瞬开 3 格，[main.gd:610](../../scripts/main.gd#L610)）与检测型机器人（确认旗→矿脉的"确认"语义，[detector_robot.gd:92](../../scripts/robots/detector_robot.gd#L92)）；探测机器人=两者语义合并（瞬发+确认雷），无需外部方案。
- **巡逻/守卫单位**：塔防目标优先级（first/strong/close 型排序）为行业标配设定，本关固定"虫>锁>网>黏液+同类最近"为教学可读性服务（玩家能预测保安去向），不做可配置。
- 盘面随机与经济模拟先例沿引 [第二关-实施计划.md](第二关-实施计划.md) §8（Tatham/Kunz/Cicvárek）与 [第三关-实施计划.md](第三关-实施计划.md) §7，不重复展开。
