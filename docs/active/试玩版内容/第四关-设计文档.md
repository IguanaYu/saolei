## 1. 定位一句话

第一次有人来砸场子：裂缝看得见、锁和网开局就在场——先除害还是先扫雷，**除害也是一种投资**。

## 2. 教学目标

玩家离开本关时应理解的事（按出场顺序）：

1. 虫害从**裂缝**来（看得见、可预期），且可**除巢断根**
2. **三种虫害碰你三种东西**：网 = 显示（数字被盖，机器人失明）、锁 = 进度（格子被锁，谁都不能开/标）、黏液 = 机器人（3×3 内干得慢）——雷位和数字永不变
3. **保安机器人** = 花钱买断的清道夫：在你已开区内巡逻，虫/锁/网/黏液它都清
4. **探测机器人** = 花钱买情报：3×3 强制探雷，卡死的区域可以买通，不用赌命
5. 随机地图首见：每局都是新盘（重玩价值）

| 波次 | 35s / 75s / 110s 各 1 只，**织网 → 锁匠 → 减速**（从随机存活巢爬出） | 虫速 ~2s/格；直奔**最近基地**；途中每 ~8s 施害 1 次 |

| 击杀/清除 | 点虫=击杀、点锁/网/黏液=清除，各吃 1 次玩家 CD；保安一枪一个 | **虫死不回收已放的障碍**，需单独清 |

| 起始资金 | 300 + 局外起始金币 | |

## 4. 全流程剧本

| # | 触发 | 发生什么 | UI / 文案 |
|---|---|---|---|
| 0 | 进关 | 强制第一步放基地（已开区高亮，两处裂缝同时可见）；预置网×3+锁×3 在场 | "选个位置，放下基地。" |
| 1 | 开局 | 5 次免 CD 三用其一道抉择：除巢（每巢 2 下）/ 清预置虫害 / 正常扫雷 | "裂缝里有虫。" |
| 2 | 首波 35s | 巢未除则织网虫爬出、沿路盖数字；玩家点杀或等保安进已开区拦截 | 无 |
| 3 | 中段 | 钱到 80/100：保安 / 探测 / 第 2 台机器人 / Lv3 升级——四个同价档同池竞争 | "雇个保安？" |
| 4 | 后波与卡壳 | 锁匠锁路、减速虫拖慢军团；机器人停摆/磨蹭时：点清、买探测、或亲自推理破局 | （首次停摆 ≥5s）"卡住了？探测，三格见雷。" |
| 5 | 开满 160 格（v2.2） | 结算 + 时间加分 + 敌人数据行 + 探测次数 | 无 |

## 5. 边界情况与处理

| 情况 | 处理 |
|---|---|
| 不放基地 | 进关强制第一步，无法跳过（机器人无出生点、虫无目标） |
| 除巢后 | 该巢波次取消；双巢皆除 = 再无新虫；场上已有锁/网/黏液仍需清 |
| 锁住关键格 / 锁住雷 | 机器人停摆 + 警示；玩家点锁（CD）或保安清——永有出路，不死锁 |
| 黏液格交互 | 可正常开/标，仅 3×3 内机器人减速；多片黏液重叠不叠乘（仍 ×2） |
| 保安不进未开区 | 未开区深处的障碍：等 frontier 推到，或玩家点清；虫进已开区才可被保安射杀 |
| 随机盘真歧义 | 探测买通；没钱 → 推理或猜（命兜底）；命尽强停结算非失败，重玩开新图 |
| 探测滥用 | 全盘约 28 次 ≈ 2800，价格自限，不限购 |
| 探测与锁 | 情报穿透锁可见雷位，但锁本身仍需单独清除 |
| 确认雷格再插旗 | 不重复给分（同格首次原则） |
| 保安忙碌 | 一次只处理一个目标，漏的玩家补——保安不完美，手动有活 |
| 敌人与棋盘 | 虫害只碰显示层（网）、进度层（锁）、机器人层（黏液），**不碰棋盘真值**（⑥ 合规：锁=交互阻断位掩码，网=显示遮罩，黏液=速度修正） |

## 6. 教学文案（定稿）

1. 进关："选个位置，放下基地。"
2. 首波前："裂缝里有虫。"
3. 首波后："雇个保安？"
4. （首次停摆 ≥5s 且未买过探测）："卡住了？探测，三格见雷。"

文案原则：全关 ≤ 4 句；三种虫害的效果不用文字解释，机器人停摆/磨蹭 + 图标自证。

## 7. 盘面方案（随机，不设生成时过滤）

2026-09-27 定：**裸随机，就这样试试，有问题再说**（用户拍板）。

- 生成：40 雷随机布 → 从一个安全格洪水预开（起点保证非雷；连通展开自然落多少算多少，**不卡比例**）
- 裂缝 ×2 随机落在盘边两条不同边
- 不跑 solver 过滤、不重摇

原过滤条款全部转为**盲测观察项**（出问题再决定加过滤还是调参数）：

1. 预开比例的自然分布（过小 → 改为多起点洪水；过大 → 无碍）
2. 2 规则残留歧义簇数（过多 → 探测降价 / 加命 / 再考虑过滤）
3. ≥6 格连锁是否常见
4. 裂缝与可放基地区的距离（过近 → 反应窗口不足，虫瞬到基地）

> **离线模拟基线（2026-09-28，`tmp/level4_sim.py`，200 盘采样，逐 tick 模型）**：
> - §7-1 预开占比：中位 15.6%，**52% 的盘 <15%**——最小仅 2.3%。「多起点洪水」预案大概率在盲测后触发
> - §7-2 歧义簇：中位 1 / 均值 1.59 / max 7，PASS（探测兜底压力可控）
> - §7-3 ≥6 格连锁：100% 常见，PASS
> - §7-4 裂缝距离：中位 3 格，PASS（个别盘 1-2 格靠运气）
> - **§8.4 双路线 150s 清完率：0/200（双路线均报警）**——瓶颈为推理枯竭后的玩家 CD 手动推进
>   （3s/格 × 剩余 ~80 格）与机器人长距离移动（预开小 → frontier 分散）。模型未含和弦/高级推理，
>   真人强于模型，但 150s 全清预期仍非常紧——**盲测重点观察项**，大概率触发调参
>   （对策按代价排序：时限 150→240s / 多起点洪水 / 免 CD 次数 5→10）；到点强停无惩罚 + 重玩 50 矿
>   是当前兜底。静态算术（§8.1/8.3）全 PASS。
>
> **2026-09-30 报警处置（v2.2）**：实机盲测后落地"时限 150→180s + 目标打折为开 160 格（≈77%）"双管齐下（提交 903757f）——§8.4 的"150s 清完"口径随之作废，盲测观察点改为"180s 内开满 160 格的实测通关率"。

## 8. 经济与节奏验收（转交执行侧）

1. **除害三路线成本同量级**：速除双巢（4 CD）≈ 保安（80 钱）＜ 硬扛（预置 6 + 波次虫 3 + 衍生障碍约 6-9 ≈ 15-18 CD + 机器人停摆/减速损失）——保安划算，但除巢流/点杀流都可行
2. 同价抉择带：保安 80 / 基地 80 / 探测 100 / Lv3 升级 100 / 第 2 台机器人 100
3. 预算延续：清空收入 416 + 起始 300+局外 vs 4 轨全满 880 + 保安 80——装不下，必须取舍
4. 双路线可行：solver 模拟"开局速除双巢 + 保安"与"全程手动点杀"均能在时限内达标（模拟基线为 150s 全清口径、0/200 报警——v2.2 已改 180s + 160 格阈值处置，以盲测实测为准）
5. 探测需求：裸随机下歧义簇数不定——探测作为主兜底，盲测观察其购买率与卡壳时长

## 9. 实现需求清单（转交执行侧）

1. **敌虫实体（织网虫/锁匠虫/减速虫）**：巢出生 / 奔最近基地 / 定时施害 / 点击击杀（吃 CD）/ 保安击杀；**虫死不回收已施障碍**
2. **格子状态扩展**：锁（交互阻断，不动真值）/ 网（显示遮罩）/ 黏液（3×3 机器人速度修正 ×2，不叠乘）——与雷位数字解耦的独立状态位
3. **巢实体**：HP、点击摧毁、与波次表联动（巢毁则取消后续波次）
4. **保安机器人**：**仅已开格寻路**巡逻、索敌优先级（虫>锁>网>黏液）、射程 4 格开火、1.5s/发
5. **探测机器人**：一次性瞬发，3×3 雷位「确认雷」标记（新标记类型：机器人规则视同旗、不计分、可穿锁）
6. **随机生成器**：40 雷随机 + 安全起点洪水预开，无过滤（观察项见 §7）
7. **基地自放模式**：开局强制第一步（仅已开格），放置完成后开商店与机器人出生
8. **Director 剧本**：波次时点表（三虫顺序）、裂缝亮起、预置虫害放置、四句文案触发
9. **点击优先级**：虫/锁/网/黏液/巢命中盒 > 格子；全部吃玩家 CD（与开格共用同一 CD）
10. 盲测埋点：巢除时点、保安购买时点、探测购买次数与坐标、击杀数、清障数、机器人停摆/减速时长
11. 沿用：meta_progression / 4 轨升级 / CD 系统 / 强停结算 / 清空目标通道（复用 L1/L2）
