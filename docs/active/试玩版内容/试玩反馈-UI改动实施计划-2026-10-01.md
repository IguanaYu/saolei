## A：设置与升级面板，以及浮层生命周期

**覆盖：P1-01、P1-02、P1-03。**

| 涉及文件 | 具体改动 |
| --- | --- |
| `scenes/ui/SettingsPanel.tscn`、`scripts/ui/settings_panel.gd` | 设置项放入可滚动内容区，返回按钮固定在面板底部；面板最大高度随可用窗口调整。重排节点后同步更新所有信号和 `@onready` 路径 |
| `scenes/ui/UpgradePanel.tscn`、`scripts/ui/upgrade_panel.gd` | 替换固定 440×340 的面板布局；动态 RowsBox 使用受约束的列表区，关闭按钮留在列表之外；升级名称、等级与购买按钮分别分配宽度，长文字不能撑出右框 |
| `scripts/main.gd`、`scripts/ui/shop.gd` | 统一清理局内浮层与放置预览；结算、退出、重玩及新局开始都调用。升级面板打开时主动按当前关刷新，避免沿用上一关条目；ESC 优先关闭当前升级浮层，再按已有规则返回/暂停 |

**已核实的原因**：升级行的三列最小宽度加列间距、面板内边距超过当前面板宽度；动态增加行后，固定高度也不足。`_start_level_with()` 未收起升级面板，`_handle_escape()` 未单独处理它。

**实施注意**：只清理当前局相关状态，规则/设置等已有返回与暂停逻辑保持一致。若改成 PanelContainer，同时调整脚本继承；新增节点使用明确名字，不通过宽泛的 `get_children()` 查找控件。

**验收**：两种已测窗口尺寸及全屏，设置和全部升级项可访问；满级/缺钱文字不溢出；升级面板打开后超时、重玩、退回菜单或换关，旧面板与预览均不残留。设置页重看引导、清存档按钮的既有确认流程仍有效。

## B：商店与棋盘共用布局边界

**覆盖：P1-04、P1-05；顺带处理 P2-06 的试玩不可解锁卡片。**

| 涉及文件 | 具体改动 |
| --- | --- |
| `scenes/ui/Shop.tscn`、`scripts/ui/shop.gd` | 将价格、数量、差额/禁买原因分区显示，约束卡片宽度；宽屏单排，窄屏按实际宽度换行。建基地/升级/说明行与模式提示分别布局，商店提供实际占用边界 |
| `scripts/ui/shop.gd` | 试玩模式中收起五关无法解锁的检测型/矿工卡；保留正式关卡的既有解锁逻辑，第四/五关的保安与探测继续按关卡配置显示 |
| `scripts/grid.gd`、`scripts/main.gd`、`scenes/Main.tscn` | 将棋盘居中依据从整个 viewport 改为扣除 HUD、侧栏与商店后的可用区域；把棋盘外框和高亮边距计入预算，关卡变化、窗口变化、商店高度变化后重算 |
| `scripts/cave_env.gd`、`scripts/ui/tutorial_guide.gd` | 在棋盘布局完成后重排洞窟边框与教学高亮；保持高亮目标、气泡和真实控件位置一致 |

**已核实的原因**：Shop 使用固定底部高度，卡片文本会改变最小尺寸；Grid 的 `_center_grid()` 按整个 viewport 居中，没有扣除商店占用。只抬高棋盘或加高商店会留下其他关卡与窄窗口问题。

**实施注意**：优先统一可用区域，再决定是否需要棋盘显示缩放。若引入缩放，必须一起验证鼠标到格子的坐标转换、机器人/敌虫/Boss 定位、边框及特效，不能只缩棋盘纹理。商店提示从隐藏变显示时也要触发布局刷新；教学锚点若随场景结构迁移，同步更新目标路径。

**验收**：第一关购买前后、第三关教学、第四/五关保安与探测入口出现时，卡片不横向溢出；棋盘底行与外框不压商店；高亮不压卡片标题。小窗口下首先保证关键操作可达，不能靠裁切按钮或单纯缩小文字通过。

## 验收与交付节奏

每批实施后做对应回归，填写优先清单状态；A/B/C 全部通过后才可将本轮 P1 标为解除。最终再做一次五关连续路径验收，补上此前未实际完成的第五关胜利与试玩完成页。

| 维度 | 必测内容 |
| --- | --- |
| 显示 | 1024×768、1280×960、全屏；设置支持的1536×1152/跟随屏幕也复核；项目允许的640×480作为边界检查，不能静默提高最小窗口绕过 |
| 窗口变化 | 打开面板时切换窗口尺寸/F11；第三、四关教学中切换；探测预览中切换 |
| 商店状态 | 未买、已购满、差额、余额改变、保安/探测出现、提示行显示/隐藏 |
| 流程 | 主菜单直接开始→ESC；结算→下一关；升级打开→超时/退出/重玩/换关；末关完成→返回 |
| 信息 | 第三关预开格分；第五关各战斗加分；时间奖励；保安状态；时间到/命尽文案 |
| 数据保护 | 用隔离测试目录或备份并恢复原存档及设置；通过文件哈希确认恢复；不改用户正式进度 |

布局检查保存修复前后截图，像素级重叠按项目守则输出 bbox/剖面等中间结果，确认对象后再判断。针对关卡导航、得分合计做必要逻辑验证；UI 仍以实际窗口点击和截图为准。发行包只在本轮改动稳定后交给已有构建主线验收。
