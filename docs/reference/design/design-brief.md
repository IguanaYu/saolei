# 扫雷挖矿 · Game Design Brief

> **版本**：v1.0
> **创建日期**：2026-08-11
> **文档定位**：game-design pipeline Layer 1，所有后续分析（teardown / loop / economy / uiux / benchmark / synthesis）都 resolve 回本文档的战略张力
> **证据来源**：用户体感目标原话（对标调研 §1.1）+ 游戏设计文档 + 对标调研 + 代码实现

---

## 1. 设计目标类型

**主导：优化现有**

P1-P12 已实现（扫雷核心 + 4 种机器人 + 矿脉产业链 + 局外矿石 + 升级树 + 解锁），但存在三个结构性问题：
- 90 秒单局太短，产业链雪球跑不起来
- 关卡章节容器缺失（P13 正在补）
- 升级质变感不足

**次要：做新功能**--P13 关卡章节系统 + 未来的装备/角色流派/社交。

当前阶段不是从零设计，也不是纯竞品调研，而是**带着已实现的原型找方向**。

## 3. 核心体验目标

### 玩家动机（Quantic Foundry 6 簇）

| 动机 | 权重 | 说明 |
|---|---|---|
| **Mastery** | ★★★★★ 主导 | 扫雷推理的智力成就感 + 产业链布局策略 |
| **Achievement** | ★★★★ 强 | 矿石升级 + 60 关推进 + 模块解锁 |
| **Immersion** | ★★ 中 | "扫雷挖矿"的 Fantasy（从劳工到矿场老板） |
| **Submission** | ★★ 中 | 看机器人自动作业的解压感 |
| **Action** | ★ 弱 | 90s 倒计时的轻度紧迫感 |
| **Social** | ✗ | 当前完全缺失，后期补 |
| **Creativity** | ✗ | 当前缺失，无角色流派/build 多样性 |

### 核心情绪

**掌控感**--从"我手点攒钱"到"我部署机器人替我赚钱"的身份跃迁。玩家在 30 秒级感受到"我又开了一片"的即时反馈，在 5 分钟级感受到"产业链运转起来了"的满足，在 30 分钟级感受到"我变强了，回来碾压"的爽快。

### 反情绪（玩家绝不能感受到的）

- **无聊**：机器人接管后玩家无事可做（当前 90s 后期的真实风险）
- **焦虑**：90s 太紧，产业链来不及启动就 timeout
- **被坑**：80 块买的 detector 自爆消失（§15.3 已识别风险）
- **重复劳动**：60 关内容雷同，刷矿石变成苦力

### 用户体感目标（原话）

> "玩一关，打不过但是感觉能过；退出来之后，就能升级；升级之后游戏里有很大的提升，然后很轻松过了；又碰到困难，玩两轮三轮，解锁系统，升级之后又轻松通过了。"

这是典型的小游戏式心流：**近失感 -> 局外成长正反馈 -> 碾压式回归 -> 解锁新系统再卡关**。每一个设计决策都要回答"这服务的是这四个环节中的哪一环"。

## 4. 商业约束

| 维度 | 当前 | 目标 |
|---|---|---|
| **变现** | 无（先做产品本身） | 未来 IAA（激励视频）+ IAP（月卡/战令/去广告） |
| **目标用户** | - | 微信小游戏休闲偏中度用户（25-45 岁，碎片时间游玩） |
| **平台约束** | 横屏 2D、鼠标 | 竖屏/横屏待定（需适配手机触屏）、单局 3-8 分钟 |
| **发布节奏** | - | 长线运营（60 关 MVP -> 持续更新章节） |
| **留存基准** | - | 次留 30%+（益智品类优秀线 >40%）、7 留 60%+ 头部 |

### 关键约束

1. **微信小游戏入口**：80% 用户通过社交分享/下拉入口发现游戏，Social 模块虽后期补，但架构层要预留
2. **碎片时间**：单局必须能在 3-8 分钟内完成，不能要求连续 30 分钟专注
3. **性能档位**：需适配低端安卓机，4 种机器人 + 建筑同屏的渲染压力要控制

## 5. 战略张力（最重要）

### 主导张力：慢思考 × 快节奏

```
        慢思考（扫雷推理派）
              ↑
              │
              │     ● 扫雷挖矿目标位置
              │     （保留扫雷推理内核，
              │      但包装进快节奏容器）
              │
   ───────────┼───────────→ 快节奏（小游戏数值爽感派）
              │
              │     ● 当前位置（偏左：
              │      扫雷推理太重，
              │      数值爽感没跑起来）
              │
        快节奏（小游戏派）
```

**两极定义**：
- **慢思考极**：扫雷的推理确定性、智力成就感、低随机性、每一次操作都有意义
- **快节奏极**：小游戏的数值滚雪球、强反馈、卡关-升级-碾压循环、碎片时间可玩

**为什么必须同时持有两极**：
- 只持慢思考 = 扫雷 purist 体验，3 天玩完，无留存，无法支撑 60 关 + 局外养成
- 只持快节奏 = 又一个割草小游戏，没有差异化，被弹壳/Survivor.io 直接碾压
- **扫雷挖矿的唯一差异化在于"把扫雷的推理确定性嫁接到小游戏的数值滚雪球上"**--少任何一极都不是这个游戏

### 次要张力

| 张力 | Pole A | Pole B | 当前偏向 | 目标 |
|---|---|---|---|---|
| **B. 短局 × 长线** | 3-8 分钟单局 | 50+ 小时长线养成 | 偏短（90s 太短） | 右移到 3-5 分钟 |
| **C. 失败 × 近失** | 踩雷硬失败 | 失败也给奖励 | 偏硬失败 | 强化近失补偿 |
| **D. 确定性 × 随机** | 扫雷推理可预测 | 地雷分布随机 | 平衡 | 保持 |

### 目标象限

在主导张力 2×2 图上，目标位置是**右上偏右**：保留中等程度的扫雷推理内核（不是纯扫雷，机器人接管了确定性操作），但强化快节奏数值爽感（拉长单局、拉大升级幅度、强化产业链雪球）。

### Drop-the-pole 失败模式

- **慢思考-only**：做成纯扫雷 + 关卡制，没有局外养成 -> 3 天玩完，留存崩盘
- **快节奏-only**：砍掉扫雷推理，纯数值滚雪球 -> 没有差异化，被竞品碾压
- **两者都弱**：90s 太短 + 升级幅度太小 -> 既不够慢思考也不够爽，当前最大的风险

## Framing Principle（框架原则）

> **扫雷挖矿的唯一差异化在于"把扫雷的推理确定性嫁接到小游戏的数值滚雪球上"。**
>
> 每一个设计决策都要回答：这个决策是强化了"扫雷推理的智力成就感"，还是强化了"小游戏的数值爽感"？如果两者都不服务，这个决策就是在稀释核心定位。
>
> 当前最大的结构性风险是"两者都弱"--90 秒太短让扫雷推理被压缩、数值雪球跑不起来；升级幅度太小让"变强"体感缺失。后续所有分析的优先级排序都以"先解决这个两头不讨好"为准。
