# 扫雷挖矿 · Feature Benchmark：局外解锁链跨游戏对比

> **分析对象**：5 款游戏的"系统/模块逐步解锁"机制
> **证据来源**：L1 = 设计文档 / L2 = 代码实现 / L3 = 对标调研 + 规划文档
> **分析日期**：2026-08-11
> **使用框架**：game-feature-benchmark skill

---

## 1. Scope（功能边界）

> **我们对比「局外解锁链（系统/模块如何逐步解锁给玩家）」在「Roguelite + 微信小游戏」品类中的实现，聚焦于「解锁结构（并列 vs 嵌套）、解锁触发器、解锁节奏、对新手的引导效果、长线目标感」。**

### Brief 张力轴

**主导张力：慢思考（扫雷推理） × 快节奏（小游戏数值爽感）**

解锁链直接服务这个张力：
- **嵌套解锁链**服务慢思考--每个解锁点是"我理解了上一个系统，准备好学下一个"的里程碑
- **解锁节奏**服务快节奏--每 10-30 分钟一个新系统，让玩家持续有"又变强了"的爽感

## 3. 对比维度（Comparison Dimensions）

基于功能特性生成 6 个维度：

| 维度 | 含义 | 为什么重要 |
|---|---|---|
| **D1. 解锁结构** | 并列 vs 嵌套 vs 混合 | 嵌套链让每个解锁点触发下一个需求，避免"解锁后空虚" |
| **D2. 解锁触发器** | 关卡/任务/等级/时间/使用 | 触发器决定玩家"怎么到达解锁点"的体验 |
| **D3. 解锁节奏** | 新系统解锁间隔（分钟/小时） | 太密=新手懵，太疏=无聊 |
| **D4. 新手引导效果** | 解锁即教学？还是需要额外引导？ | 好的解锁链本身就是教程 |
| **D5. 长线目标感** | 解锁后有无"下一个目标"牵引 | 决定 10+ 小时留存 |
| **D6. 玩家可控性** | 玩家能选解锁顺序吗？ | 可控性建立"我的成长路线"感 |

## 4. 各游戏实现详解

### 4.1 弹壳特工队 / Survivor.io [L3 对标调研 §4.1]

**解锁方式**：关卡解锁
- 第 6 关解锁每日挑战
- 第 8 关解锁回响之战 + 特工赛季
- 装备品阶通过合成升级（白->绿->蓝->紫->金->红->S）

**玩家看到的**：章节地图上锁图标，通关第 N 关后图标消失，新系统按钮亮起

**玩家做的**：推关卡 -> 卡关 -> 回刷升级 -> 推过 -> 新系统解锁

**系统做的**：关卡序号达成即解锁，无选择空间

**为什么有效**：关卡制容器让解锁有明确"里程碑感"，卡关节点（27/30/46/71/123）让解锁有"来之不易"感

**哪里失败**：解锁后系统立即可用，无教学引导；新玩家面对突然出现的新系统可能困惑

### 4.2 吸血鬼幸存者 [L3 对标调研 §4.2]

**解锁方式**：嵌套解锁链
```
解锁角色 A -> 角色主武器升满级 -> 武器合成超武 -> 解锁新角色 B -> ...
```

**玩家看到的**：解锁时弹成就横幅 + 新角色/武器在列表中亮起

**玩家做的**：用 A 通关 -> 获得 B -> 用 B 通关 -> 获得 C -> ...

**系统做的**：解锁条件多样化（找 500 金币/通关特定地图/一局获得 5000 金币/武器升满级）

**为什么有效**：**每个解锁点自然触发下一个需求**--解锁角色 A 后，玩家想升满 A 的武器，升满后想合成超武，合成后解锁新角色 B。链条环环相扣，玩家永远有"下一个目标"

**哪里失败**：后期解锁条件过于隐晦（如"击败 25 分钟 Boss"），需要查攻略

### 4.3 寻道大千 [L3 对标调研 §4.3]

**解锁方式**：主线任务数解锁
- 6 任务 -> 冒险
- 10 任务 -> 幻境阁
- 19 任务 -> 座驾
- 26 任务 -> 福地
- 28 任务 -> 斗法（PVP）
- 153 任务 -> 血脉
- 开服 26 天 + 156 级 -> 法宝

**玩家看到的**：主线任务进度条 + "完成 N 个主线任务解锁 X"提示

**玩家做的**：砍树/推图 -> 攒主线任务数 -> 新系统解锁 -> 用新系统推更远

**系统做的**：三类触发器组合（任务数 + 等级 + 开服天数）

**为什么有效**：**每个新系统解锁 = 战力大跃升 + 对旧系统二次加成**。新系统不是孤立的，会反向加成老系统，让老系统也有"重新值得玩"的理由

**哪里失败**：后期（153 任务/开服 26 天）解锁间隔过长，玩家可能流失

### 4.4 Hades [L3 对标调研 §4.5]

**解锁方式**：玩家可控解锁
- 死亡给黑暗宝石（局外货币）
- 玩家选择先解锁全武器，还是先解锁镜面天赋
- 通关后开启"热度"系统（主动加难度）

**玩家看到的**：屋内 NPC 对话解锁内容，选择花货币解锁什么

**玩家做的**：死亡 -> 获得货币 -> 选择解锁武器或天赋 -> 下一局用新装备

**系统做的**：解锁路径分支，玩家自选优先级

**为什么有效**：**玩家可控性建立"我的成长路线"感**。死亡是资源化（每次死都给货币），解锁不是"系统给我"，而是"我选择要什么"

**哪里失败**：解锁选项过多可能让新手选择困难；分支解锁需要足够内容量支撑

### 4.5 扫雷挖矿（当前 P13 设计）[L2 level_system.gd / L3 P13 任务文档]

**解锁方式**：章末通关解锁
```
ch01_s05 通关 -> 解锁 ch02 + opener/marker（默认有）
ch02_s05 通关 -> 解锁 ch03 + detector
ch03_s05 通关 -> 解锁 ch04 + miner
ch04_s05 通关 -> 解锁 ch05 + tower（功能未实现）
ch05_s05 通关 -> 解锁 ch06 + drone
```

**玩家看到的**：结算面板"🎉 新功能解锁: 检测型机器人" [L2 results_panel.gd:76-78]

**玩家做的**：通关章末 -> 新模块解锁 -> 下一关可用新模块

**系统做的**：章末触发解锁，模块与章节绑定

**为什么有效**：**模块与章节绑定，让每个章节有"主题"**（ch02=矿脉、ch03=产业链、ch04=充能塔、ch05=无人机）

**哪里失败**：
- 解锁后无教学引导（detector 解锁了，但玩家不知道"标雷->检测->矿脉"的产业链流程）
- 充能塔解锁但功能未实现 [L2 game_state.gd:48]
- 解锁是线性的，无玩家选择空间
- **关键缺陷**：解锁链不是真正的"嵌套"--解锁 detector 不会"触发" miner 的需求，只是"下一关刚好解锁 miner"

### 评分锚点说明

- **D1 解锁结构**：5=真正嵌套（A 触发 B 需求）/ 3=并列 / 1=纯线性
- **D2 触发器**：5=多样化且有意义 / 3=单一但有效 / 1=单一且无趣
- **D3 节奏**：5=前密后疏且有内容支撑 / 3=均匀 / 1=过密或过疏
- **D4 新手引导**：5=解锁即教学 / 3=有文字说明 / 1=无引导
- **D5 长线目标**：5=永远有下一个 / 3=有但有限 / 1=很快耗尽
- **D6 可控性**：5=完全可选 / 3=部分可选 / 1=完全线性

## 6. 跨游戏综合（Synthesis）

### 最佳实践（Best Practices）

1. **嵌套解锁链 > 并列解锁** [吸血鬼幸存者]
   - 解锁 A 后，A 的使用自然产生对 B 的需求
   - 避免"解锁后空虚"--每个解锁点都是下一个目标的起点

2. **解锁即教学** [Hades]
   - NPC 对话介绍新系统，玩家"边玩边学"
   - 比纯文字 tooltip 更沉浸

3. **死亡/失败资源化** [Hades / 吸血鬼幸存者]
   - 每次失败都给局外货币，让解锁不卡关
   - 失败不是"惩罚"，而是"下次变强的资源"

4. **新系统反向加成老系统** [寻道大千]
   - 新系统不是孤立的，会反向激活老系统的价值
   - 让老内容有"重新值得玩"的理由

5. **多样化触发器** [吸血鬼幸存者 / 寻道大千]
   - 不要只用一种触发器（如纯关卡数）
   - 混合"通关/达成/使用/时间"让解锁有惊喜感

### 反模式（Anti-Patterns）

1. **解锁后无引导** [弹壳 / 扫雷挖矿]
   - 新系统突然出现，玩家不知道怎么用
   - 导致新系统被忽略或误用

2. **纯线性无选择** [弹壳 / 寻道大千 / 扫雷挖矿]
   - 玩家无法选择"先解锁什么"
   - 缺乏"我的成长路线"感

3. **伪嵌套** [扫雷挖矿当前]
   - 看似嵌套（章末解锁），实则只是"下一关刚好解锁"
   - 解锁 A 不真正"触发"对 B 的需求

4. **后期解锁间隔过长** [寻道大千 153 任务]
   - 玩家可能在新系统来之前就流失
   - 需要中期内容填补

### 白空间（White Space）

**未被任何游戏占据的设计空间**：

1. **基于使用的解锁**：没有游戏用"使用 A 系统 N 次 -> 解锁 B"作为触发器。扫雷挖矿可以尝试：用 marker 标 N 次雷 -> 解锁 detector（因为 detector 验证的就是 marker 的标记）

2. **解锁链可视化**：没有游戏给玩家展示"解锁地图"--玩家不知道"接下来还能解锁什么"。在章节选择页显示"未来可解锁的系统预览"可以增强长线目标感

3. **解锁失败的容错**：所有游戏的解锁都是"达成即解锁"，没有"解锁失败"的概念。可以考虑"detector 验证失败 N 次 -> 解锁保险机制"（将失败转化为解锁进度）

## 7. Brief Resolution（设计简报回应）

### 哪款游戏最适合扫雷挖矿？

**吸血鬼幸存者的嵌套解锁链模式最适合**，因为：
- 扫雷挖矿的 4 种机器人天然有"使用 A 产生 B 需求"的关系：
  ```
  opener 开格 -> 暴露数字 -> marker 标雷 -> detector 验证 -> 矿脉 -> miner 运货
  ```
- 这条链可以设计成真正的嵌套解锁：
  ```
  用 opener 开 N 格 -> 解锁 marker
  用 marker 标 N 次雷 -> 解锁 detector
  用 detector 验证 N 次成功 -> 解锁 miner
  拥有 N 个 miner -> 解锁充能塔
  ```

**Hades 的玩家可控解锁**是愿景标杆，但当前 60 关的内容量撑不起分支解锁树。

### 必须采纳的模式（无论 brief 如何）

1. **解锁后必须有引导**--当前最大缺陷。detector 解锁时应该弹一次性引导"标记雷 -> 检测 -> 矿脉"流程
2. **解锁反馈必须有视觉冲击**--当前只有 🎉 文字 [L2 results_panel.gd:76]，应加成就横幅滑入 [L3 UI_UX §4.4-J]

### 差异化机会

扫雷挖矿可以做**"基于使用的嵌套解锁链"**：
- 不完全靠章末通关解锁
- 额外加"使用次数"触发器：用 marker 标 10 次雷 -> 提前解锁 detector
- 这让玩家有"多玩就能解锁"的额外动力，不完全卡在关卡进度上

### 推荐实现方向（1-2 段概要）

**当前 P13 的章末解锁保留作为"主线解锁"**，额外加一层"使用次数解锁"作为"支线解锁"：

1. **主线解锁**（保留）：通关 ch02_s05 -> 解锁 detector。保证章节主题感。
2. **支线解锁**（新增）：用 marker 标 20 次雷 -> 提前解锁 detector。让高玩可以跳过等待。
3. **解锁引导**（新增）：detector 解锁时弹一次性教程气泡，高亮"标记雷 -> 检测 -> 矿脉"流程。
4. **解锁链可视化**（新增）：章节选择页显示"未来可解锁的系统预览"，增强长线目标感。

这样既保留了 P13 的章节容器结构，又增加了嵌套解锁的"触发需求"感和玩家可控性。
